# API 与接口契约规范

## 契约

API 必须明确资源、版本、认证上下文、请求参数、响应结构、错误码、幂等性和兼容策略。接口命名应稳定、可预测，避免把内部数据库结构直接暴露为公共契约。

统一说明：分页使用 page/pageSize 或项目已确认的游标方案；列表必须有上限；时间和时区使用明确的标准格式；写操作在可能重试时提供幂等键；错误响应不得泄漏堆栈或敏感数据。

外部依赖调用必须设置超时、重试上限和可识别的关联 ID。破坏性字段变更需版本化、迁移或兼容过渡，并更新 API 文档和示例。

## 验收

验证正常、校验失败、未授权、资源不存在、重复请求、超时、分页边界、兼容旧客户端和错误响应格式。
