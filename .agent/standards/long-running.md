# 长任务执行规范

## 适用范围与能力边界

预计持续数小时、需要跨上下文恢复或明确要求无人值守的任务，必须同时遵循 orchestration.md 和本规范。规范定义授权内的执行行为与长任务监督器契约；规范本身不提供进程保活、自动唤醒或崩溃恢复服务，持续运行能力以实际部署的监督器和演练证据为准。只有验证执行器支持持续调度、后台作业管理、检查点存储和恢复后，才能声明具备对应无人值守能力；不得仅凭文档承诺连续运行 8 小时。

## 启动与授权

启动前检查工作目录、已有用户修改、所需工具、依赖、测试命令、存储空间及执行器能力。将目标拆成有依赖关系的可验收阶段，每阶段记录输入、输出、完成条件、验证命令、预计时长和恢复点。提前集中确认业务决策、允许修改范围、禁止操作和验收标准；已经批准的普通实施与修复不重复请求批准。

任务简报必须记录预算及生效时间。以下为可采用的建议值，须纳入已批准计划，不能默认为无限授权：

| 项目 | 建议值与含义 |
| --- | --- |
| 最大运行时长 | 8 小时墙钟时间，记录 startedAt 和 deadlineAt，等待与重启不重置截止时间 |
| 自动重试 | 同一失败原因最多追加 3 次尝试，记录累计次数 |
| 并行上限 | 2 个工作任务，明确文件归属并预留集成验证 |
| 检查点间隔 | 最多 30 分钟，建议每 15 分钟记录 |
| 无进展阈值 | 30 分钟触发诊断，不以心跳或重复执行充当进展 |
| 收尾时间 | 截止前预留 15 分钟，保存状态、收集结果、停止作业 |
| 资源预算 | 明确令牌/费用、磁盘和外部调用上限；未知时不得声称可控制 |

最大时长是上限，目标提前完成就结束。预算仅允许已批准的开发、测试和局部修复，不授权发布、生产操作、数据删除、权限变更或新增费用。

## 持久状态与检查点

每个任务使用独立目录，避免并行任务覆盖：

```text
.agent/tasks/<task-id>/
  task-state.json
  decisions.md
  execution-log.md
  checkpoints/
```

这些是业务工作区运行记录，由执行者创建，不由规范同步脚本覆盖。不得记录密钥或未脱敏生产数据。

状态至少包含 schemaVersion、taskId、修订号、执行者/运行标识、授权范围与证据引用、startedAt、deadlineAt、预算、阶段及依赖、任务状态、已改文件、验证命令/退出码/证据路径、失败分类与重试累计、后台作业 ID、最近心跳、lastProgressAt、下一步、暂停原因和恢复条件。状态区分 pending、running、paused、failed、completed；已实现但未验证不能记为 completed。

每项任务或阶段完成、重要命令启动前后、异常发生及间隔到期时保存检查点。长命令未结束时记录仍在运行及作业 ID；命令返回前不标通过。执行器负责定时心跳，Agent 只在调度到时记录真实状态，不伪造后台定时能力。

状态更新采用单写者与修订检查，先写临时文件校验后原子替换，保留上一有效版本；工具不支持时明确限制。执行日志追加记录关键决策、错误、修复假设和验证结果；不以自动提交 Git 代替检查点，提交按用户授权执行。

## 执行、重试与无进展处理

按依赖运行任务，完成一项验证一项，失败时先定位原因再修复。每条命令设超时，长命令使用受管理后台作业，记录启动目录、用途和 ID；不得重复启动仍在运行的相同工作，也不得忙轮询。

仅对临时网络失败、可安全重放的下载或服务启动按有限退避重试。确定性的构建/测试失败须先提出并实施有依据的修复；不得重复原命令消耗预算。端口冲突先确认归属，不杀死未知进程。非幂等操作、权限拒绝、业务歧义及超授权操作不能自动重试或绕过。

每次修复记录失败原因、措施及新证据。同一原因达到重试上限后暂停受影响任务，其他独立且获批任务可以继续。新增诊断证据、验证通过、缺陷原因被证实均属于进展，单纯改文件或刷新心跳不算。达到无进展阈值先检查作业状态、输出及资源，进行有界诊断；仍无安全可行路径则保存状态暂停，不能无限循环。

## 中断与恢复

会话恢复、进程崩溃或上下文切换后，先读最近有效状态、决策和检查点，再核对当前工作目录、代码修改、已完成操作及后台作业实际状态。禁止凭旧记录重复写入数据、启动作业或覆盖用户修改。状态损坏回退上一有效版本，不能推断已完成。

同一任务只能有一个有效执行者；调度器须用租约或等价互斥机制避免双执行。仅在授权仍有效、预算未耗尽、执行器允许恢复且幂等性已确认时继续。原截止时间、重试次数与费用累计必须保留；平台要求人工重新激活时遵循平台规则。自动恢复需要实际的监督进程/调度器，任务文件本身不能重启 Agent；监督进程必须符合「长任务监督器」契约。

## 长任务监督器

监督器是运行在业务工程侧的外部进程，在执行者回合结束后按已批准计划继续推进任务，解决“单个回合结束即整体停止”的问题。公共规范只定义本契约；实现由独立工具仓库或参考实现提供，业务工程也可自建，但行为必须符合本节并通过验收节的验证。

监督器不是批准主体。其全部授权来自用户在任务简报和执行授权中预先批准、并记录于 task-state.json 的范围与预算；续跑仅表示继续已批准范围，不构成对新增范围、验收标准变更或高风险操作的批准。未记录明确执行授权的任务不得启用监督器。执行平台明确要求人工重新激活时，不得以监督器绕过。

| 职责 | 要求 |
| --- | --- |
| 回合续跑 | 回合结束且仍有 pending/running 的已批准任务、依赖就绪、预算未耗尽且无暂停条件时，按适配器发起新回合；状态为 paused、failed、completed 或触发暂停条件时不得发起。 |
| 预算记账 | 独立核算墙钟时长、重试累计、并行数与资源费用，不依赖执行者自报；到达收尾预留时间时注入收尾指令，超预算不再发起。监督器重启不重置任何累计值。 |
| 停滞检测 | lastProgressAt 超过无进展阈值时注入有界诊断指令；仍无有效进展则置为 paused 并汇报原因，不得无限重试。 |
| 互斥 | 通过租约或等价机制保证同一 task-id 同一时间至多一个监督器和一个执行者；租约获取失败或丢失时立即停止发起并报告。 |
| 监督日志 | 每次发起、拒绝发起、暂停与停止都追加记录时间、原因和所依据的状态修订号，写入监督器自身日志，不覆盖执行者状态文件。 |

监督器不得：修改授权范围、验收标准或决策记录；在暂停条件下续跑；伪造进展、心跳或验证结果；跳过状态核对直接重跑命令；终止未知归属的进程。

执行器适配接口由业务工程实现，至少覆盖：以非交互方式启动一轮执行、注入续跑指令、获取回合结束信号。续跑指令必须包含 task-id、状态目录，以及等价于以下内容的约束：“先读取最近有效状态并核对实际工作区与后台作业，只继续已批准范围内的工作；遇到暂停条件立即保存状态并停止，不得自行扩大范围。”适配器不得注入超出已批准范围的任何指示。

监督器自身崩溃不得破坏任务状态；重启后按「中断与恢复」核对再继续或收尾。用户撤回授权后，监督器立即停止发起新回合，并引导在收尾预留时间内完成收尾。

## 会话内长任务（主 Agent 派发子 Agent）

除外部监督器宿主形态外，长任务也可以由交互界面中的主 Agent 派发子 Agent 运行：主 Agent 承担调度与用户反馈，子 Agent 执行具体工作，同处一个会话。该形态过程可见、可随时询问纠偏，但**随会话结束而终止——无人值守能力（关闭窗口、跨重启持续运行）仍且仅由外部监督器提供**；两种形态互补，本规范的授权、预算与恢复纪律对两者同样适用。

- **派发**：主 Agent 按 `orchestration.md` 拆分并派发子 Agent，逐一明确目标、范围与禁止事项；子 Agent 写任务按泳道隔离并行，只读工作不限。
- **执行日志**：子 Agent 执行期间必须向业务项目 `logs/<task-id>/progress.md` 追加写工作日志，每完成一个有意义步骤记一条，格式 `时间 | 做了什么 | 结果 | 下一步`。子 Agent 的过程输出对主 Agent 与用户均不可见，该日志是过程可见性的唯一通道；日志随项目落盘，用户可直接打开查看。
- **反馈**：用户询问进度时，主 Agent 读取相关子 Agent 日志，以日志实际内容作答，不得凭记忆或推测描述；收到子 Agent 完成通知时立即汇总结果与验证证据。主 Agent 除完成通知外不主动定时播报，除非用户另行配置。
- **纪律承接**：主 Agent 在会话内承担监督器同等纪律——不超出已批准范围派发或续派；为每个任务独立核算时长预算与重试次数；子 Agent 长时间无有效进展或连续失败时暂停并报告原因，不静默重派；派发记录与完成证据保留在任务清单与日志文件中，会话结束后仍可完整还原工作状态。

## 暂停、停止与交付

新增业务决策、范围变化、高风险操作、授权撤回、预算耗尽、无可用依赖、资源不足、重复失败上限或恢复状态冲突时保存检查点，说明原因、影响和恢复条件。普通实现困难或首次测试失败不等于任务阻塞。用户要求停止时及时停止；预计无法在剩余预算内安全完成的阶段不再启动。

停止前收集仍相关的作业输出，取消不再需要且属于本任务的作业及子任务；记录无法停止的任务及其影响，不误杀共享服务。仅清理本任务创建且可安全删除的临时资源。最终报告区分已修改、已测试、已构建和待验收，逐项提供证据；预算用尽但验收未过必须报告未完成。

## 验收

执行器或长任务流程接入时验证：检查点可读且可恢复；崩溃后不重复副作用；并行执行不会争用同一状态；短预算到期能收尾；重试上限有效；长命令可取消并收集输出；无进展诊断与真实进展可区分；超授权操作会暂停；所有通过结论均有证据。部署监督器时追加验证：单个任务完成后自动继续下一个已批准任务；预算到期或触发暂停条件时停止发起；并发第二个监督器被互斥拒绝；监督器崩溃重启后不重复副作用；监督日志可追溯每次发起与停止的原因和状态修订号。短时演练不能冒称 8 小时稳定性验证；需要承诺 8 小时能力时另行记录实际持续运行和中断恢复的演练结果。会话内长任务追加验证：子 Agent 日志随执行及时追加；主 Agent 的进度回答与日志内容一致；会话结束后凭日志与任务清单可完整还原工作状态。
