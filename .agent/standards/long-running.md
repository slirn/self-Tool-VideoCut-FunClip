# 长任务执行规范

## 适用范围与能力边界

预计持续数小时、需要跨上下文恢复或明确要求无人值守的任务，必须同时遵循 orchestration.md 和本规范。规范定义授权内的执行行为，不提供进程保活、自动唤醒或崩溃恢复服务。只有验证执行器支持持续调度、后台作业管理、检查点存储和恢复后，才能声明具备对应无人值守能力；不得仅凭文档承诺连续运行 8 小时。

## 启动与授权

启动前检查工作目录、已有用户修改、所需工具、依赖、测试命令、存储空间及执行器能力。将目标拆成有依赖关系的可验收阶段，每阶段记录输入、输出、完成条件、验证命令、预计时长和恢复点。提前集中确认业务决策、允许修改范围、禁止操作和验收标准；已经批准的普通实施与修复不重复请求批准。

任务简报必须记录预算及生效时间。以下为可采用的建议值，须纳入已批准计划，不能默认为无限授权：

| 项目 | 建议值与含义 |
| --- | --- |
| 最大运行时长 | 8 小时墙钟时间，记录 startedAt 和 deadlineAt，等待与重启不重置截止时间 |
| 自动重试 | 同一失败原因最多追加 3 次尝试，记录累计次数 |
| 并行上限 | 2 个工作任务，明确文件归属并预留集成验证 |
| 检查点间隔 | 最多 30 分钟，建议每 15 分钟记录 |
| 无进展阈值 | 30 分钟触发诊断，不以心跳或重复执行充当进展 |
| 收尾时间 | 截止前预留 15 分钟，保存状态、收集结果、停止作业 |
| 资源预算 | 明确令牌/费用、磁盘和外部调用上限；未知时不得声称可控制 |

最大时长是上限，目标提前完成就结束。预算仅允许已批准的开发、测试和局部修复，不授权发布、生产操作、数据删除、权限变更或新增费用。

## 持久状态与检查点

每个任务使用独立目录，避免并行任务覆盖：

```text
.agent/tasks/<task-id>/
  task-state.json
  decisions.md
  execution-log.md
  checkpoints/
```

这些是业务工作区运行记录，由执行者创建，不由规范同步脚本覆盖。不得记录密钥或未脱敏生产数据。

状态至少包含 schemaVersion、taskId、修订号、执行者/运行标识、授权范围与证据引用、startedAt、deadlineAt、预算、阶段及依赖、任务状态、已改文件、验证命令/退出码/证据路径、失败分类与重试累计、后台作业 ID、最近心跳、lastProgressAt、下一步、暂停原因和恢复条件。状态区分 pending、running、paused、failed、completed；已实现但未验证不能记为 completed。

每项任务或阶段完成、重要命令启动前后、异常发生及间隔到期时保存检查点。长命令未结束时记录仍在运行及作业 ID；命令返回前不标通过。执行器负责定时心跳，Agent 只在调度到时记录真实状态，不伪造后台定时能力。

状态更新采用单写者与修订检查，先写临时文件校验后原子替换，保留上一有效版本；工具不支持时明确限制。执行日志追加记录关键决策、错误、修复假设和验证结果；不以自动提交 Git 代替检查点，提交按用户授权执行。

## 执行、重试与无进展处理

按依赖运行任务，完成一项验证一项，失败时先定位原因再修复。每条命令设超时，长命令使用受管理后台作业，记录启动目录、用途和 ID；不得重复启动仍在运行的相同工作，也不得忙轮询。

仅对临时网络失败、可安全重放的下载或服务启动按有限退避重试。确定性的构建/测试失败须先提出并实施有依据的修复；不得重复原命令消耗预算。端口冲突先确认归属，不杀死未知进程。非幂等操作、权限拒绝、业务歧义及超授权操作不能自动重试或绕过。

每次修复记录失败原因、措施及新证据。同一原因达到重试上限后暂停受影响任务，其他独立且获批任务可以继续。新增诊断证据、验证通过、缺陷原因被证实均属于进展，单纯改文件或刷新心跳不算。达到无进展阈值先检查作业状态、输出及资源，进行有界诊断；仍无安全可行路径则保存状态暂停，不能无限循环。

## 中断与恢复

会话恢复、进程崩溃或上下文切换后，先读最近有效状态、决策和检查点，再核对当前工作目录、代码修改、已完成操作及后台作业实际状态。禁止凭旧记录重复写入数据、启动作业或覆盖用户修改。状态损坏回退上一有效版本，不能推断已完成。

同一任务只能有一个有效执行者；调度器须用租约或等价互斥机制避免双执行。仅在授权仍有效、预算未耗尽、执行器允许恢复且幂等性已确认时继续。原截止时间、重试次数与费用累计必须保留；平台要求人工重新激活时遵循平台规则。自动恢复需要实际的监督进程/调度器，任务文件本身不能重启 Agent。

## 暂停、停止与交付

新增业务决策、范围变化、高风险操作、授权撤回、预算耗尽、无可用依赖、资源不足、重复失败上限或恢复状态冲突时保存检查点，说明原因、影响和恢复条件。普通实现困难或首次测试失败不等于任务阻塞。用户要求停止时及时停止；预计无法在剩余预算内安全完成的阶段不再启动。

停止前收集仍相关的作业输出，取消不再需要且属于本任务的作业及子任务；记录无法停止的任务及其影响，不误杀共享服务。仅清理本任务创建且可安全删除的临时资源。最终报告区分已修改、已测试、已构建和待验收，逐项提供证据；预算用尽但验收未过必须报告未完成。

## 验收

执行器或长任务流程接入时验证：检查点可读且可恢复；崩溃后不重复副作用；并行执行不会争用同一状态；短预算到期能收尾；重试上限有效；长命令可取消并收集输出；无进展诊断与真实进展可区分；超授权操作会暂停；所有通过结论均有证据。短时演练不能冒称 8 小时稳定性验证；需要承诺 8 小时能力时另行记录实际持续运行和中断恢复的演练结果。
