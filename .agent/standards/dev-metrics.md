# 开发效能度量规范

## 目的与边界

度量用于发现流程瓶颈、验证协作规范改动的实际效果，不用于考核个人，不作为绩效依据。指标异常触发的是流程改进讨论，不是对执行者的追责。

## 核心指标

- **首次验收通过率**：首次运行即通过的验收项占全部验收项的比例。反映交付质量的前置水平。
- **返工率**：验收未通过而需要返工的任务占已完成任务的比例。反映质量成本。
- **周期时间**：从任务受理确认到最终验收通过的时长。反映端到端流转速度。
- **每任务回合数**：单个任务消耗的 Agent 执行回合数（多任务计划按任务拆分统计）。反映切片粒度与上下文组织是否合理。

## 数据来源与采集

- 全部指标从既有记录自动汇总，不新增人工填报步骤：验收结果来自验收记录，回合、暂停与恢复来自任务清单和监督日志（`long-running.md`）；
- 日志平台可从统一事件中聚合上述指标，不重复建通道；
- 数据不全时如实标注缺失范围与原因，不得估算填充。

## 使用方式

- 月度回顾查看趋势而非单点数值，并与规范改动对照（如泳道并行、模式清单引入、监督器接入）验证效果；
- 指标连续恶化时先检查流程与任务切片粒度，再检查工具与上下文供给；
- 改进决定写入项目上下文或按 `technical-debt.md` 登记，形成度量—改进闭环。
