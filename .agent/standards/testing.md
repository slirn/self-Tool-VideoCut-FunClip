# 测试策略规范

测试应围绕可观察行为覆盖正常、失败、边界、权限、兼容性和回归。按风险选择单元、集成、API、数据库、端到端、性能、安全、契约和故障注入测试。

测试数据必须隔离且可重复；默认不访问真实生产服务。测试失败不得标记为通过，环境限制必须单独说明。覆盖率只能辅助判断，不能替代关键行为验收。

公共模块、数据结构、权限、接口契约和配置变更必须增加对应回归验证。

## 不稳定测试（Flaky）治理

同一测试在代码未变的情况下重复运行结论不一致（偶发失败、偶发超时、依赖执行顺序或环境残留）判定为不稳定测试，按以下规则处理：

- **判定与取证**：连续运行同一测试至少 3 次结论不一致即隔离；隔离决定必须附失败输出与环境说明，不得只凭单次失败判定。
- **隔离区**：不稳定测试移入隔离清单，记录测试标识、负责人、隔离日期和修复时限（建议两周）；隔离测试不计入合并门禁的必需检查，但必须在验证证据中单独可见，不得静默跳过。
- **修复时限**：超期未修复的隔离测试移除或重写，不允许长期滞留；移除时按 `technical-debt.md` 登记影响。
- **Agent 行为**：Agent 遇疑似不稳定测试必须先固定证据——重跑取证、核对隔离清单、排查顺序与环境依赖——禁止为消除偶发失败直接修改产品代码；新引入的不稳定测试由引入泳道当场隔离并登记。
