# 前端质量、可访问性与性能规范

## 目的

本规范定义前端应用的兼容范围、可访问性、国际化、响应式布局、状态体验、性能预算、安全和验收要求。

## 支持范围

项目必须明确：

- 浏览器和最低版本；
- 桌面、平板和移动端范围；
- 屏幕尺寸、缩放和触控要求；
- 网络条件和离线能力；
- 支持的语言、时区和地区；
- 渐进增强或明确不支持的功能。

兼容范围之外的行为不得静默损坏，应有提示或降级。

## 可访问性

目标至少为 WCAG 2.2 AA 或项目批准的等价标准：

- 键盘可完成核心流程；
- 焦点可见、顺序合理、不被遮挡；
- 表单有标签、错误说明和关联关系；
- 非文本内容有等价文本；
- 颜色不是唯一信息载体；
- 文本和组件对比度达标；
- 动态内容变化可被辅助技术感知；
- 尊重减少动画设置；
- 触控目标大小合理；
- 页面缩放和重新排版不丢失内容。

## 国际化与本地化

- 文案不得硬编码在组件内部，使用统一资源机制。
- 日期、时间、数字、货币和排序使用地区和时区规则。
- 后端和前端明确时区边界，存储使用明确标准。
- 支持复数、性别、语序和长文本扩展。
- 布局必须容纳更长翻译文本。
- RTL 或双向文本如适用，必须有布局和图标镜像策略。
- 不将机器翻译结果未经审核用于法律、安全或高风险内容。

## 响应式与布局

- 使用弹性布局、约束和断点，不以固定像素模拟所有屏幕。
- 文本不能溢出、截断关键含义或遮挡其他内容。
- 固定格式控件定义稳定尺寸，加载、错误和动态内容不能导致布局跳动。
- 表格、图表、画布和长流程在移动端有明确替代或导航方式。
- 页面适配缩放、横屏和软键盘。

## 状态与反馈

每个数据视图至少定义：

- 初始加载；
- 空状态；
- 成功状态；
- 部分成功或降级；
- 可恢复错误；
- 不可恢复错误；
- 离线或网络中断（适用时）；
- 权限不足和资源不存在。

提交、删除、发布等高风险操作必须防止重复提交，并明确处理中、成功、失败和重试。

## 性能预算

项目必须基于真实用户指标定义预算，至少包括适用的：

- LCP、INP、CLS；
- 首屏 JavaScript、CSS、字体和图片体积；
- 路由或页面包体积；
- API 延迟和瀑布请求；
- 长任务、主线程阻塞和内存；
- 缓存命中率和离线恢复。

预算必须与设备、网络和地区分档验证。性能回归应能通过 CI 或发布门禁发现。

## 前端安全与隐私

- 防止 XSS、危险 HTML、URL 注入和脚本注入。
- 使用 CSP、Trusted Types 或其他适用的浏览器防护。
- 认证 Token 的存储和刷新策略必须明确。
- 跨站请求必须考虑 CSRF、SameSite 和来源校验。
- 不在前端日志、埋点、URL、本地存储或错误上报中记录敏感数据。
- 埋点和第三方脚本必须经过隐私、安全和性能评估。
- 权限隐藏不能替代服务端授权。

## 设计系统与组件

- 颜色、间距、字体、层级和状态使用设计令牌。
- 可复用组件定义键盘、焦点、禁用、加载、错误和国际化行为。
- 图标按钮有可访问名称或提示。
- 卡片、弹窗、抽屉和表格遵循一致的交互和层级。
- 不使用只有视觉含义的颜色或装饰表达业务状态。

## 测试与验收

至少覆盖适用的：

- 单元和组件测试；
- 关键用户旅程端到端测试；
- 键盘和辅助技术检查；
- 自动可访问性扫描和人工抽样；
- 多语言、长文本、时区和 RTL；
- 桌面、移动、缩放和软键盘；
- 弱网、错误、离线和重试；
- 性能预算和视觉稳定性；
- XSS、CSRF、敏感信息和第三方脚本边界。

## 完成标准

- 支持范围和兼容策略明确；
- 核心流程可键盘完成且通过可访问性检查；
- 文案、日期、数字、时区和 RTL 按项目范围正确处理；
- 文本和控件在目标视口内不溢出、不重叠；
- 加载、空、错误、降级和权限状态完整；
- 性能预算可测量并有回归证据；
- 前端不泄漏敏感数据，服务端仍是最终授权边界。
