# 知识放置与记忆边界规范

## 目的

本规范用于约束项目知识的产生位置，确保对团队和项目长期有效的知识进入项目仓库并接受版本管理，防止其落入 Agent 工具的用户级目录（如各 Agent 工具在用户主目录下的记忆、笔记和计划目录），造成无版本历史、不共享、不随仓库备份和多源漂移。

## 判定原则

写入任何知识前先回答：这条知识换一个开发者、换一台机器、换一个 Agent 工具，还有效吗？

- 有效：属于项目资产，必须写入项目仓库受版本管理的位置。
- 无效（依赖个人环境、个人偏好或单一工具行为）：属于个人记忆，可保留在 Agent 工具的用户级目录。
- 两者混合：拆分后分别放置，不得因为混合而整体留在用户级目录。

Agent 在向用户级记忆、笔记或计划目录写入前必须执行本判定；不确定时按项目资产处理并写入仓库。

## 放置矩阵

| 知识类型 | 唯一落点 | 说明 |
| --- | --- | --- |
| 项目事实、结构、技术栈、常用命令 | `.agent/project-context.md` | 项目事实的唯一权威来源 |
| 架构约束、接口约定、模块边界 | `.agent/project-context.md`，重要者另立 ADR | 稳定约束优先 ADR |
| 协作规则、流程适配、规范例外 | `.agent/standards-profile.md` | 已有 `AGENTS.md` 只补充受管区块外的项目内容 |
| 需求、任务和执行记录 | 项目流程规定的目录（如 `requirements/`、`design/`、`.agent/tasks/`） | 不在用户级目录沉淀任务状态 |
| 技术坑与回归教训 | 优先转化为测试或可执行检查；无法自动化时写入项目文档 | 测试优先于文档 |
| 重要技术决策 | 决策记录（ADR）目录 | 见 `decisions.md` |
| 个人环境特性、个人操作偏好 | Agent 工具的用户级记忆目录 | 不得作为项目事实被引用 |

## 用户级记忆的边界

Agent 工具在用户主目录下的记忆、笔记和计划目录只允许保存：

- 用户个人的操作与沟通偏好；
- 个人机器、网络和工具环境特性；
- 与项目仓库无关的工具使用习惯。

不得保存：

- 项目事实、架构约束和接口约定；
- 需求结论、任务状态和执行历史；
- 对其他开发者、评审或后续任务有价值的教训；
- 密钥、令牌和敏感数据（同时见 `agent-runtime-security.md`）。

## 禁止双源与指针例外

- 同一事实只在项目仓库维护一处；`.agent/project-context.md` 是项目事实的唯一权威来源。
- 用户级记忆中允许保留指向仓库文档的指针（文件路径加一句话用途），但指针不承载事实，内容以仓库为准。
- 发现仓库与用户级记忆冲突时，以仓库为准，并当场修正或删除过期记忆。

## 记录时机

- 知识归位是任务收尾的一部分：需求记录、决策、教训必须在任务闭环前落盘，不依赖事后补录。
- 评审和验收检查知识落点是否正确，未归位的知识不得视为任务完成。

## 存量迁移

发现已落入用户级目录的项目知识时：

1. 按判定原则逐条分类；
2. 迁移到放置矩阵指定的落点，随正常开发流程提交；
3. 无法直接迁移的教训转化为测试或可执行检查；
4. 用户级记忆中仅保留指针，或删除原记录；
5. 迁移范围、去向和剩余豁免在迁移清单中留痕。

## 审计

至少在每次规范升级和阶段性验收时检查：

- 用户级记忆目录中是否存在项目知识；
- `.agent/project-context.md` 是否覆盖当前实际依赖的项目事实；
- 是否存在与仓库冲突或重复的记忆；
- 技术坑是否已有对应测试或检查。

## 验收

- 项目知识全部位于仓库内受版本管理的位置；
- 用户级记忆目录不含项目事实、需求记录和团队教训；
- 项目事实单一来源，无双源冲突；
- 可自动化的技术坑有对应测试或检查；
- 新知识在任务收尾前完成归位，迁移有留痕。
