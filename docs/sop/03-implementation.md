# 阶段 3：实现

**目标**：照设计写代码，并保证可自测通过。

## 入口条件

- `design/DESIGN-<id>.md` 已批准
- 受影响文件清单明确

## 产出

- 代码改动（含新增文件）
- 单元测试 / 集成测试（如适用）
- 提交记录（git log）

## Checklist

### 代码风格

- [ ] 命名、缩进、风格与现有代码**完全一致**
- [ ] 关键函数有 docstring（说明意图，不是描述代码）
- [ ] 复杂逻辑有行内注释（**为什么**，不是**是什么**）
- [ ] 没有"调试用"的 print / pdb 残留

### 改动范围

- [ ] 改动局限在 `design/DESIGN-<id>.md` 列表内
- [ ] 没有顺手的"小优化"（除非写在设计里）
- [ ] 没有引入新依赖（除非已批准）

### 错误处理

- [ ] 每个外部调用有 try/except 或显式错误检查
- [ ] 错误信息包含**足够上下文**（哪个文件、什么操作、相关 ID）
- [ ] 关键路径有日志（INFO 级别）

### 可测试性

- [ ] 关键函数可独立 import 测试
- [ ] 至少 1 个用例覆盖正常路径
- [ ] 至少 1 个用例覆盖异常路径
- [ ] 边界条件有测试（空字符串、None、极大值）

### 文档

- [ ] 如新增 Skill，写 SKILL.md
- [ ] 如新增 CLI，写 help 文本和 README 更新
- [ ] 如修改 API，写 changelog

### 自测

- [ ] `./.venv/Scripts/python.exe -m pytest tests/ -v` 通过
- [ ] 手动跑一次端到端示例（用 [02-design.md](02-design.md) 里的例子）
- [ ] 跑过 ruff format（如果项目装了 ruff）

### 提交

- [ ] 提交信息符合 Conventional Commits（见 [CLAUDE.md §6](../../CLAUDE.md)）
- [ ] 每个 commit 单一目的（不混合多个不相关改动）
- [ ] 没有把生成产物（mp4/srt/log）提交

## 出口条件

- [ ] 所有测试通过
- [ ] 改动局限在设计范围内
- [ ] 提交记录清晰

## 反例

- ❌ "顺手优化"了一段没在设计里的代码
- ❌ 加了新依赖但没在设计里说明
- ❌ 错误处理只写了 `except: pass`
- ❌ 测试只覆盖了 happy path
