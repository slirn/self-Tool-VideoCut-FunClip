## 1. 需求原话

> 第二步是针对切分修剪的字幕根据修剪前和修剪后的文字比较决定这段。字幕所对应的时间段要切分成多段，切分之后把每一段也做上相关的建议标记，例如是保留还是删除，基本就这两种状态。通过这种切分修剪，可以把这一段字幕中的字或者是词在视频上这个时间段的时间截出来，可以手工删掉，删掉不需要的。针对整段字幕拆分之后的细分字幕，它的序号才是加上点1.2.3这样的，同时，原来的序号10还是存在的，作为父级。而这个父级切分之后的各个子段是十点一十点二十点三。

第一步（决策到清单）已在 REQ-20260916-008 完成：修订阶段决策为「保留/内容更正」的整段带入，「删除」的不带入，「切分」的按修剪后文字切子段。**本设计只解决第二步**。

> 追加需求（同日）：切分时间戳确认来自视频；预览要能**播放截取之后的视频片段确认切分效果**（播放参考字幕修订区的播放效果）；要能**针对选中的原片段记录、重新填写切分后内容、单片重新切分**。→ 见第 2 节「时间戳从哪来」与第 7 节「预览确认」「单段重新切分」。

> 追加需求（同日二）：切分修剪阶段还需要**重新执行切分修剪**的功能。→ 见第 7 节「重新执行切分修剪（整单重算）」。

> 追加需求（同日三）：预览播放时**视频中音频对应的字幕要高亮跟随**；把修订阶段的**上一句/下一句/播放暂停快捷键**带过来；**每条需切分的字幕行上要有明确的重新切分入口**——修改切分后文字 → 点重切 → 该条字幕按新内容切成多段 → 同样可预览。→ 见第 7 节「预览确认」「单段重新切分」。

### 时间戳从哪来（用户问：是根据视频中提取的吗？——是）

字级时间戳产自**字幕生成阶段**：FunASR 对任务视频的**音频轨**做识别时，为每个字/词给出在视频里的起止毫秒，落盘在 `subtitle.json` 的 `segments[].tokens` / `token_ts`（`_segment_tokens` 校验的正是这两列）。切分算法不产生新时间——只是**在这些已有时间戳上划边界**。因此：

- 预览播放 = 播放器 seek 到同一段 (start_ms, end_ms)，**所听即剪辑所得**（预览确认的就是真实切分效果）；
- 时间戳的精度上限 = FunASR 字级时间戳精度（通常 ±20ms 内，听感无断裂）；
- 旧任务无字级时间戳 → 无法精确切分，走 fallback 整段（见第 9 节），重新生成字幕即可补齐。

## 2. 现状与差距

当前 `build_cutlist` 对 split 段的处理（`cutlist_service.py:167-201`）：

```
原文 15 个单字 token（各带字级时间戳）   修剪后文字
大 家 好 今 天 我 们 来 讲 一 下       "今天我们讲这个话题"
这 个 话 题   （索引 0–14）
    ↓ align_tokens（贪心子序列匹配）
命中索引 3,4,5,6,8,11,12,13,14
    ↓ contiguous_blocks
保留块 (3,6)=今天我们  (8,8)=讲  (11,14)=这个话题
    ↓ 只产出这三个块
子段：10.1 今天我们   10.2 讲   10.3 这个话题   ← 现状只到这里
（"大家好"“来”“一下”＝隐式空洞，无编号无时间段无标记）
```

**差距**：被剪掉的字/词（上例的"大家好"、"来"、"一下"）是隐式空洞——清单上看不到它们、没有编号、没有时间段。用户要求的是**完整划分**：父段时间轴全部切成子段（含删除部分），每段有编号（父.N 按时间序）+ 双态建议标记（保留/删除），并能手工翻转标记，从而实现"把某个字/词的时间段截出来、手工删掉"。

## 3. 核心逻辑（先把逻辑讲清楚）

一句话：**用修剪后文字在原文字里做"划线对照"——划中线的进保留组，没划中的进删除组，然后按时间顺序把原段的所有字不重不漏地切成交替的子段。**

三步：

1. **对齐**（已有，不变）：修剪后文字 tokenize 成 token 序列（中文单字/英文连字），在原段 token 序列里做**贪心子序列匹配**（保序、不回溯）。修剪本质是"原文子集 + 去语气词/重复"，子序列匹配足够；用户改写导致对不上的 token 自然落进删除洞，行为可预期。
2. **完整划分**（新增）：命中索引聚成连续块（保留块）；保留块之间的间隙（含首尾）就是删除洞。原段全部 token 被分成 **keep 块 / delete 洞交替**，不重不漏。
3. **时间边界**（新增规则）：keep 块时间 = 块内首 token 起点 → 尾 token 终点（现状口径不变）；**delete 洞采用外扩边界**——洞起点 = 前一 keep 块尾 token 的终点（首洞用父段 start_ms），洞终点 = 后一 keep 块首 token 的起点（尾洞用父段 end_ms）。

为什么洞要外扩：keep 段定义不动、父段时间轴被 keep/delete **完全二分**（相邻段共享边界、无重叠无缝隙）；删掉所有 delete 段后 keep 段自动首尾紧贴——这正是"把那段时间从视频上剪掉"的语义。token 之间的静默间隔也随洞一起删掉，不会残留在成片里。

**编号**：按时间顺序父.1、父.2、父.3…**不分标记**（10.1 可以是删除段）。翻转某段标记不改变任何编号——编号是位置，标记是决策，两者解耦，用户手工调整时不会"一删编号全变"。

**建议标记（mark）推导**：块来自命中 → 建议 `keep`；洞 → 建议 `delete`。即模型建议的修剪文本决定初始标记，用户手工翻转后以手工为准。

## 4. 算法与代码

新增一个纯函数（复用现有 `contiguous_blocks`）：

```python
def partition_tokens(n_tokens: int, keep_marks: list[int]) -> list[tuple[str, int, int]]:
    """命中索引 → 完整交替划分 [(mark, 首 token 索引, 尾 token 索引), …]。

    覆盖 [0, n_tokens) 不重不漏：keep 块（命中连续块）与 delete 洞
    （块间/首/尾的间隙）交替；编号阶段直接按本列表顺序产 父.N。
    """
    parts: list[tuple[str, int, int]] = []
    cur = 0
    for a, b in contiguous_blocks(keep_marks):
        if a > cur:
            parts.append(("delete", cur, a - 1))
        parts.append(("keep", a, b))
        cur = b + 1
    if cur < n_tokens:
        parts.append(("delete", cur, n_tokens - 1))
    return parts
```

时间边界换算（`build_cutlist` 的 split 分支改造）：

```python
segs = partition_tokens(len(orig_tokens), align_tokens(orig_tokens, tokenize(target)))
seg_start_ms, seg_end_ms = int(seg.get("start_ms", 0)), int(seg.get("end_ms", 0))
prev_e = seg_start_ms                       # 前一段的终点（初始=父段起点）
for k, (mark, a, b) in enumerate(segs, start=1):
    if mark == "keep":
        s_ms, e_ms = token_ts[a][0], token_ts[b][1]           # 现状口径
    else:
        # 外扩：向前贴住前一段的终点、向后贴住后一段 keep 块的起点
        s_ms = prev_e
        e_ms = token_ts[b + 1][0] if b + 1 < len(token_ts) else seg_end_ms
    s_ms = max(s_ms, prev_e)                # ts 非单调防御
    if e_ms - s_ms > 0:                     # 零长洞（相邻 token 无缝）不产段
        items.append({
            "id": f"{i}.{k}", "source_i": i, "kind": "split", "sub": k,
            "mark": mark,                   # ← 新增字段（keep/delete）
            "start_ms": s_ms, "end_ms": e_ms,
            "start": ms2srt(s_ms), "end": ms2srt(e_ms),
            "text": join_tokens(orig_tokens[a:b + 1]),
            "orig_text": str(seg.get("text", "")), "target_text": target,
            "fallback": False,
        })
        prev_e = e_ms
```

父段 10 原文：`大家好今天我们来讲一下这个话题`——按 `_TOKEN_RE` 口径为 **15 个单字 token**（中文单字、英文连字），段边界 [10.0s, 19.6s]。
模型建议修剪后文字：`今天我们这个话题` → 命中索引 3,4,5,6（今天我们）与 11,12,13,14（这个话题）→ 保留块 (3,6) 与 (11,14)。

| 子段 | 标记 | token 索引 | 时间（示意） | 文本 |

| 10.1 | ❌ delete | 0–2 | 10.0 → 13.2 | 大家好 |
| 10.2 | ✅ keep | 3–6 | 13.2 → 15.0 | 今天我们 |
| 10.3 | ❌ delete | 7–10 | 15.0 → 16.1 | 来讲一下 |

## 6. 数据模型变更

`cutlist.json` 的 split 子段 item 新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `mark` | `"keep" \| "delete"` | 本段最终标记（建议推导 + 手工翻转后落盘） |
| `mark_manual` | bool | 是否手工翻转过（重建统计用） |

keep/fix 整段不带 mark（恒为保留，语义已由 kind 表达）。清单顶层新增 `manual_marks: {"<source_i>.<sub>": "keep"|"delete", …}`——**手工决策单独存**，`build_cutlist(sub_meta, rev, manual_marks=…)` 重建时按 (source_i, sub) 恢复手工翻转；重新生成清单会提示将清除手工决策（与 REQ-20260916-010「重新分析=重置全部」同一哲学）。stats 增加 `split_subs_delete`（洞段数）与 `mark_flipped`（手工翻转数）。

## 7. UI 与交互（切分修剪面板）

- **按父段分组**：组头 = 父编号 + 原文 + 建议（剪掉→保留文本摘要）+ 操作（▶ 试听保留效果 / ✂️ 重新切分）；组内子段表。
- **子段行**：`10.2` ｜ 起止时间 ｜ 文本 ｜ 建议徽章（✅ 保留 / ❌ 删除，delete 行降透明度+删除线）｜ 操作：`▶ 预播`、`翻转标记`。

### 预览确认（播放基础设施已存在，扩展即可）

切分修剪面板**已有**独立播放器 `#slirn-cut-player` 与行定位播放 `playCutAt()`（REQ-20260916-008，与字幕修订区同模式：点行 → seek 到行起点播放、`/slirn/api/video/<tid>` 流式源支持拖动）。本设计在其上补四项：

1. **字幕高亮跟随**：播放器 timeupdate → 找 `currentTime` 落在哪个子段 `[start_ms, end_ms]` → 该行高亮 + `scrollIntoView({block:'nearest'})` 长列表自动跟随（与字幕生成/修订区同款实现，绑 `slirn-cut-player`）。keep 段正常高亮；**delete 段高亮时保留删除线/降透明样式**——一眼可辨"正在播的是将被删除的内容"。keep/fix 整段行同样参与跟随（整段一条）。
2. **快捷键（整套照搬修订区键位）**：`↑` `↓` 上一条/下一条（选中行移动并跳到该段起点，播放态跟随）、`空格` 播放/暂停、`R` 重播本行。**仅在切分修剪面板激活时生效**（工作台同一页面修订区/切分区都有键位，按当前 pane 分发，互不抢键）。
3. **段级预播 `▶ 预播`**：复用 playCutAt 定位到段起点，加一次性 timeupdate 监听——播到本段 `end_ms` 自动暂停。逐段确认"这个字/词截得对不对、删得冤不冤"。keep/delete 段都可预播（删除段更要点开听——确认删的正是不要的）。
4. **父段试听保留效果 `▶ 试听`**（组头）：按成片口径**连续跳播**该父段全部 mark=keep 子段——播完 10.2 自动跳 10.4，跳变即真实剪辑效果，不等同于顺序播放。实现：监听 timeupdate，`currentTime ≥ 当前段 end` 时 seek 到下一个 keep 段 start；无下一段则暂停。**这是"确认切分效果"的核心交互**（不真剪视频、零渲染成本，纯播放器 seek 模拟）。跳播过程中高亮跟随照常工作（当前播到哪段哪段亮）。

（连播整个清单所有 keep 段 = 成片总预览，属下游精剪阶段，不塞进本阶段。）

### 单段重新切分（每条需切分的字幕都有独立入口）

**入口**：每个标记为切分的父段（组头行）右侧固定操作按钮 **`✂️ 重新切分`**——不是全局功能，是**逐条字幕**的操作。

**交互流**（行内展开，不弹模态框——保留上下文，改完即见结果）：

1. 点 `✂️ 重新切分` → 该父段组头下方展开编辑区：
   - 上：**原段文字**（只读，可点 ▶ 试听原声对照）；
   - 中：**切分后内容输入框**，预填当前生效的切分后文字（`target_text`）；
   - 下：`✂️ 按新内容重新切分` 按钮 + `取消`。
2. 用户修改文字（多写少写都行——对不上的字自然落进删除洞，算法永远给出完整划分）→ 点重切 →
3. 服务端对该父段单独重跑 `align → partition → 时间边界`，**把原来这一条字幕替换成新的多段子段**（编号重排 父.1…父.N，其余父段原样不动）→ 前端**局部刷新该组子段表**——立即看到新划分 + 新建议标记；
4. **重切结果同样可预览**：新子段表带全部预览能力（逐段 ▶ 预播 / 组头 ▶ 试听保留效果 / 高亮跟随）——改完就听，听不对再改，闭环。

**落盘与联动**：

- 端点 `POST /slirn/api/resplit_segment {task_id, source_i, target_text}`：重算该父段子段并落盘 cutlist.json；
- **重新切分会重置该父段的手工标记**（划分变了，旧 mark 不再对应）——编辑区明示；其它父段的 manual_marks 不受影响；
- 新文字全对不上（命中数 0）→ 该段降级 fallback 单子段并提示，旧子段不替换，用户可取消；
- 重切后的 target_text **回写修订 entries 的 `user_note`**（单一事实源，重算清单口径 `_split_target` 不漂移）。

### 重新执行切分修剪（整单重算）

由此形成**三级调整体系**，由轻到重：**翻转标记**（不动划分，改一段去留）→ **单段重新切分**（一个父段重新划分，其余不动）→ **重新执行**（整单推倒重算）。

**触发场景**：完成后回修订阶段改了决策（清单过期）；手工标记/单段重切积累多处想全部推倒；修订被重新分析重置后想回到模型建议的初始划分。

**设计**：

- **按钮**：面板底部主按钮按状态换语义——未生成过清单时为「✅ 生成切分清单并完成本阶段」（现状）；**已生成过（outputs/cutlist.json 存在）则变为「🔄 重新执行切分修剪」**：以**当前最新修订决策**重跑 `build_cutlist` 全量重算 → 覆盖落盘 → **清除全部手工标记与单段重切结果**（有手工修改时 confirm 明示，无则直接执行）。
- **阶段状态不变**：重新执行不回退/不重复推进——已完成（ROUGH_CUT_DONE）保持已完成，重算后可继续翻转/单段重切微调。底座已具备：`build_cutlist` 端点本就可重复调用（重算+覆盖+`update_status` 幂等），只需按钮文案/入口与清除 manual_marks 的语义包装。
- **落盘与预览的关系**：面板打开即服务端现算预览（不落盘，现状）——预览永远反映最新决策；「重新执行」解决的是**落盘那份** cutlist.json 过期的问题。预览与已保存清单不一致时（修订 saved_at 晚于 cutlist created_at），列表上方黄条提示：「📝 修订决策已更新，已保存的切分清单可能过期 → 🔄 重新执行切分修剪」。
- **端点**：复用 `POST /slirn/api/build_cutlist`（加 `regen: true` 参数区分文案，或独立 `rebuild_cutlist`——实施时择一，语义相同：清 manual_marks + 重算落盘）。

### 标记翻转与其余操作

- **翻转**：点徽章/按钮即翻转，未保存纯前端；「保存切分决策」落盘 cutlist.json（扩展 build_cutlist 端点或新增 save_cut_marks）。
- **fallback 段**（无字级时间戳/对不上）：单子段 mark=keep + `fallback` 徽章，同样可整段翻转为 delete；要精确切分需回字幕生成阶段补字级时间戳，或用「重新切分」在有时间戳后重算。
- **手工删字/词**（M3 进阶）：子段内按 token 细分——点子段文本中某字/词，该 token 高亮，「从本段剔除」将该 token 前后切两刀生成三个子段（同算法同标记规则）。首版以"翻转整段 + 单段重新切分"覆盖主路径。

## 8. 下游契约（精剪字幕 / 成片阶段）

- 成片时间轴 = 所有 mark=keep 段（keep/fix 整段 + split keep 子段）按 start_ms 升序拼接；mark=delete 全部剔除（不再依赖"子段缺失=删除"的隐式语义，显式双态）。
- 精剪字幕：每个 keep 段产一条字幕（split 子段文本=join_tokens；fix 段=更正后文本），编号沿用段 id（10.2 成片后可顺序重排，属下一阶段决策）。
- 剪辑执行（ffmpeg/moviepy）：直接消费 (start_ms, end_ms) 对列表，无需再对齐。

## 9. 边界情形

| 情形 | 处理 |
|---|---|
| 无字级时间戳（旧任务） | 整段单子段，fallback=true，mark=keep（现状语义），可手工整段删 |
| 修剪后文字为空 | 同上 fallback（不猜对齐） |
| 命中数 = 0（文字全对不上） | fallback 整段——对齐失败信号，宁可不切不可错切 |
| 全部命中（修剪=原文） | 无洞，单 keep 子段（等价现状） |
| 首尾洞 | 外扩边界用父段 start_ms/end_ms 兜底 |
| 零长洞（相邻 token 无缝） | e_ms-s_ms ≤ 0 跳过，不产空段 |
| token_ts 非单调（ASR 异常） | 边界换算统一 `max(prev_e, s_ms)` 防负时长/重叠 |
| 手工翻转后重生成 | manual_marks 按 (source_i, sub) 恢复；编号漂移导致对不上的丢弃并提示 |
| 单段重新切分时文字全对不上 | 该父段降级 fallback 单子段并提示（不猜对齐），旧子段不替换——用户可取消 |
| 重新执行时修订又变回未全决策/产物缺失 | 沿用端点现有校验引导（未决策 N 条 / 缺 subtitle.json → 报错提示先补齐），不落盘不破坏旧清单 |

## 10. 实施路径

- **M1 算法层**：`partition_tokens` + split 分支产完整子段（mark 字段）+ manual_marks 恢复 + 单测（交替完整性/首尾洞/全命中/零命中/fallback/翻转恢复）。纯函数改造，`build_cutlist` 签名向后兼容。
- **M2 UI 层**：清单按父段分组渲染子段表 + 标记徽章 + 翻转 + 保存端点；播放器复用 `slirn-cut-player`——字幕高亮跟随（timeupdate，delete 段保留删除线样式）、快捷键整套照搬修订区（↑↓/空格/R，按当前 pane 分发）、段级预播（播到段尾自动停）、父段「试听保留效果」（keep 段连续跳播）；**逐条父段 `✂️ 重新切分`**：行内展开（原文 + 预填 target_text 输入框）、`resplit_segment` 端点局部刷新、回写修订 user_note；主按钮状态化（已生成→「🔄 重新执行切分修剪」，清 manual_marks 重算落盘、阶段状态不变）+ 修订更新黄条（saved_at 晚于 cutlist created_at 提示过期）。E2E 只读验证渲染与预播。
- **M3 进阶**：段内 token 细分、相邻同标记合并、键盘快捷导航（对齐修订阶段的操作手感）。
