## 0. 背景

长视频逐条人工改状态太慢：发现某区间整段都该保留/删除时，只能一条条点。
需要区间批量的能力：给起止字幕序号 + 目标状态，一次改一批。

## 1. 核心需求

| ID | 需求 |
|---|---|
| REQ-1.1 | **字幕修改阶段**：批量条 — 开始序号 + 截止序号 + 目标状态（= 决策下拉的全部状态：未决策/采纳建议/保留/删除/切分/内容更正），确认后区间内各行决策改为目标状态 |
| REQ-1.2 | **切分修剪阶段**：批量条 — 开始序号 + 截止序号 + 目标状态（✅ 保留 / ❌ 删除 / ↩️ 维持原状），确认后区间内各行状态改为目标 |
| REQ-1.3 | 确认对话先展示命中条数与目标状态，确认后才应用 |
| REQ-1.4 | 应用后未保存态与手工单条修改一致：过滤计数/徽章实时刷新，落盘走各阶段既有「保存」按钮 |
| REQ-1.5 | 区间非法（非数字/起>止/命中 0 条）→ toast 报错，不弹确认框 |

## 2. 设计要点

- **纯前端状态变更**（与单条修改同口径 — 单条决策/翻转本来就是保存前前端态），
  不新增后端端点；保存路径复用 `save_revision` / `save_cut_decisions`。
- **字幕修改**：行匹配 = 行序号（`data-i` 整数）∈ [起, 止]；应用 = 设
  `.slirn-rev-select` 值 + 行 `data-decision/data-final`（与 change 委托同算法）+
  `revFilterSync()` 一次。目标 split/fix 时空备注从模型建议预填（不展开不聚焦，
  批量不抢焦点）。
- **切分修剪**：行匹配 = 行号 `data-id` 数值（整段行 `10`、子段行 `10.1`）∈ [起, 止]，
  **或** 所属父段号 ∈ [起, 止]（"第 10 到 10 条"覆盖该段全部子段）：
  - 整段行（whole）→ 组级决策 `data-act`（keep/delete/清空=维持原状）+ 下拉同步
  - 子段行（sub）→ `data-mark`（keep/delete；维持原状 = 回 `data-mark-init`），
    复用 `cutSpkSetMark`（幂等不 toast）
  - 不批量设 split（切分需要逐段内容，批量无意义 — 要切去单条改判/重新切分）
- 应用后：切分阶段关联了人员 → `cutSpkBarRender()` 重算统计（仅计未删除口径）。
- 确认框 = `window.confirm`（应用既有习惯）。

### 设计落地说明

- 批量条 HTML：修订阶段在筛选条之后（`#slirn-rev-batch`），切分阶段在人员统计条与
  清单之间（`#slirn-cut-batch`）；共用 `.slirn-batch-*` CSS。
- 修订目标状态 = `USER_DECISIONS` 全集（默认选中「保留」）；切分目标 =
  ✅ 保留 / ❌ 删除 / ↩️ 维持原状（不批量设 split — 切分需逐段内容）。
- 批量逻辑纯前端（`revBatchApply` / `cutBatchApply` + `batchRange` 共用区间解析），
  零新后端端点；保存复用 `save_revision` / `save_cut_decisions`。
