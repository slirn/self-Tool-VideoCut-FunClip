## 1. 需求（用户原话）

> 能否实现这些快捷键的自定义设置？因为每个人对于所习惯使用的快捷键不一样，
> 所以能够自定义设置会使每个人用这个软件时都更高效。

## 2. 设计

### 2.1 交互模型

提示条尾部常驻「**⚙ 自定义**」入口 → 弹出换绑弹窗（8 个动作行：动作名 + 当前键帽）→
**点击键帽 → 键帽变「按新键…」（脉冲闪烁）→ 按一个新键即完成换绑**，提示条立即跟随。
底部「↩️ 恢复默认」一键还原、「✅ 完成」关闭。

### 2.2 键位表

- 8 个可换绑动作（与 REQ-004 键位一一对应）：上一条 `↑`、下一条 `↓`、播放/暂停 `空格`、
  重播 `R`、保留 `K`、删除 `D`、切分 `S`、退出输入框 `Esc`。
- 存储：`localStorage.slirnRevKeys`（`{"prev":"arrowup","next":"arrowdown",...}`，
  键名为 `e.key` 小写归一）。按浏览器持久化（与严谨性级别/阶段折叠记忆同一范式），
  跨会话、跨任务生效；整页刷新后提示条与监听器均按存储键位恢复。
- 读取容错：非字符串/重复键等脏数据 → 该动作回退默认键，动作表顺序先到先得。

### 2.3 可绑键与冲突规则

- **仅单键**：可打印 ASCII 单字符 + 方向/Home/End/PgUp/PgDn/Enter/Backspace/Delete/Escape；
  组合键（Ctrl/Cmd/Alt+）一律拒绝——沿用 REQ-004「修饰键放行给浏览器/系统」的原则。
- **冲突拒绝**：新键已被其他动作占用 → toast 报「已用于「XX」」+ 冲突行键帽闪红，
  **不自动交换**（交换易造成无感知的连锁改动）；被拒后保持录制态，直接按下一个键即可。
- **Esc 双语义**：录制中按 Esc = 取消录制；唯独「退出输入框」动作本身允许绑 Esc
  （否则被改绑后永远绑不回来）。非录制态按 Esc = 关闭弹窗。
- Tab 不可绑（保留键盘焦点导航）。

### 2.4 主监听器键位表驱动（重构）

REQ-004 的硬编码 `if (e.key === 'ArrowDown')…` 改为：`revKeysLoad()` 取当前键位 →
反查按键对应的动作 → 按动作分发。门控规则全部保留（输入框不劫持、长按只放行导航、
列表不可见整体失效、修饰键放行），且新增：**弹窗打开时主监听器让位**（录制监听器
capture 阶段接管全部按键，`stopPropagation` + 主监听器显式 return 双保险）。
引导 toast（「先用 ↑/↓ 选择…」「按 Esc 返回」等）改为跟随当前键位动态生成。

### 2.5 视觉

弹窗毛玻璃卡片（`--hover-bg` + `backdrop-filter`，与全站质感一致，明暗主题各校验变量）；
键帽复用提示条 `<kbd>` 芯片语言；录制态紫色描边脉冲、冲突态红色闪底。

## 3. 验收标准

- [x] AC-1 提示条有自定义入口；弹窗列出全部 8 个动作与当前键位
- [x] AC-2 点击键帽按新键即换绑；提示条、引导 toast、监听行为立即跟随
- [x] AC-3 键位持久化：整页刷新后自定义键位仍生效
- [x] AC-4 旧键失效、新键生效（换绑无残留双绑定）
- [x] AC-5 冲突拒绝且不静默交换；可一键恢复默认
- [x] AC-6 弹窗打开时列表快捷键不误触；录制中 Esc 可取消
- [x] AC-7 REQ-004 全部门控行为在键位表驱动下不回归（含方向语义 ↑上/↓下）
