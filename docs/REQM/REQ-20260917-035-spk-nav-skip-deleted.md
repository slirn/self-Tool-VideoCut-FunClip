## 0. 背景

删除非主讲人员的记录后，用「按人员ID查找 + 上一条/下一条」翻看时，
被删除的记录也会被轮流选中——用户要在删除记录之间跳来跳去地翻。
统计口径已是「仅计未删除」（REQ-033），导航却没有对应开关。

## 1. 核心需求

| ID | 需求 |
|---|---|
| REQ-1.1 | 查找框旁新增勾选「跳过已删除」（默认不勾 = 行为不变） |
| REQ-1.2 | 勾选后 上一条/下一条 只在该人员**未删除**（执行口径）的记录间循环跳转 |
| REQ-1.3 | 该人员记录全部处于删除态时给出明确提示（取消勾选可继续翻看） |
| REQ-1.4 | 重新统计/重渲染统计条时勾选状态保留 |
| REQ-1.5 | 服务端渲染（重进任务）与 JS 渲染的统计条 HTML 一致（都带勾选框） |

## 2. 设计要点

- 过滤复用 `cutRowKept(row)`（与统计口径同一函数：组 act=delete / 子段 mark=delete 均为删除态）。
- 勾选框 id `slirn-cut-spk-skipdel`；`cutSpkBarRender` 里与查找值同样做「重渲染保留」。
- 跳转 toast 追加「· 已跳过删除」标识当前口径。

## 3. 验收标准

- [x] AC-1 统计条出现「跳过已删除」勾选框（服务端渲染 + JS 重渲染一致），默认不勾
- [x] AC-2 不勾选时导航行为与旧版完全一致（含已删除记录）
- [x] AC-3 勾选后只停在未删除记录上；toast 计数 y = 该人员未删除数
- [x] AC-4 全部删除 + 勾选 → 提示「已全部删除 — 取消勾选可继续翻看」，不崩溃
- [x] AC-5 重新统计后勾选状态保留
- [x] AC-6 ruff 0 错；全量 pytest 通过；真实浏览器 E2E 覆盖勾选/不勾选两条路径
