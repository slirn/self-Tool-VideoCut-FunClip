## 0. 背景

切分修剪阶段的字幕列表目前不携带说话人信息。课程视频多为「讲师 + 学员」多人
对话，最终成片只想保留讲师内容 —— 需要在切分修剪阶段看到每条字幕是哪个人说的，
并按人员批量剔除非讲师片段。

字幕生成阶段（REQ-20260917-029）已在 `subtitle.json` 的每段携带 `spk`
（人员编号，1 起始、按首次出现顺序）。两个阶段的时间轴同源（切分清单的整段
与子段时间窗都来自 subtitle 段的时间范围），可按**时间段重叠**把人员编号
对齐到切分修剪阶段的字幕列表。

## 2. 交互与规则

- **对齐规则**：`overlap = max(0, min(endA,endB) − max(startA,startB))`，取重叠毫秒
  最大且 >0 的 subtitle 段的 `spk`；并列取时间更早的段；无任何重叠 → 不标注
  （该行不参与该人员统计）。
- **关联是即时计算、不落盘**：清单/修订变化后再次点击按钮即按最新时间窗重算；
  删除改判落盘走既有「保存切分清单」（save_cut_decisions）口径。
- **无 spk 数据引导**：`subtitle.json` 无 `spk` 字段（REQ-029 之前生成的旧任务，
  或生成时关闭了「区分说话人」）→ 点击按钮返回提示，引导去字幕生成阶段重新生成
  （打开说话人分离）。旧任务其余渲染零回归。
- **查找/导航**：只在该人员ID的行之间循环跳转（下一条到尾回到第一条）；
  高亮复用切分修剪既有行选中态（`kbsel`）。
- **重新统计**：前端按 DOM 当前 `data-spk` + 去留状态即时重算（未保存的改判
  也计入），不依赖服务端往返。

## 4. 技术方案（要点）

- 新增 `slirn_home/cut_speaker.py`（或并入 cutlist_service）：
  `link_speakers(subtitle_meta, cutlist) -> {rows: {id: spk}, stats: [{spk,total,kept}]}`
  纯函数（时间重叠对齐 + 统计），便于单测。
- API：`POST /slirn/api/cut_speaker_link {task_id}` — 服务端实时重建切分清单预览
  （与面板同口径：修订实时 + 已保存手工决策并入）→ link_speakers → 返回。
  无 `spk` 数据 → `{ok:false, error:引导文案}`。
- 面板：`_render_cutlist_zone` 操作行加按钮 `data-action="cut-spk-link"`；
  列表上方预置隐藏的 `#slirn-cut-spk-bar`（统计 chips + 查找输入 + 上一条/下一条
  + 删除 + 重新统计），由 router.js 在关联成功后填充并显示。
- router.js：`cut-spk-link`（注入徽章 + 渲染统计条）、`cut-spk-prev/next`（导航）、
  `cut-spk-delete`（改判）、`cut-spk-recount`（DOM 重算）；删除改判复用既有
  act/mark 变更路径，确保保存口径一致。
- CSS：徽章/chips/导航条样式与优化字幕阶段 wordChips 一致风格。
