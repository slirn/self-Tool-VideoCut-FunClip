# REQ-20260916-012 — 试听跳播只播一次 + 成片口径时间戳

## 需求原话

> 试听时从开始到结束，播放完毕即可，不要反复播放，并且需要让视频的时间戳与当前试听的时间戳保持一致

## 诊断

用户在任务 **20260915-001**（1581 段全部带字级时间戳，231 个切分组/713 子段/437 保留子段——大量「多保留段」组）上点组头 ▶ 试听触发。`bindCutPlayer` 的 timeupdate 跳播循环**每次从 `qi=0` 重扫**：

1. 播过第 1 keep 段尾（-30ms 提前量）→ seek 第 2 段起点 ✓
2. seek 完成的 timeupdate：`tms = seq[1].s ≥ seq[0].e - 30` **恒成立**（段时间有序）→ 立即再跳第 3 段
3. 到末段后 `qi=0` 仍命中 → **折返**第 2 段 → 段间无限乒乓

表现即用户所述：反复播放永不结束（「播放完毕即可，不要反复播放」），视频时间戳来回跳变与当前试听段对不上（「时间戳保持一致」）。注：任务 20260915-002 全部 fallback 单段组（seq 长度 1），不触发该路径——此前 M4 E2E 只测了 002，漏网。

（诊断过程中确认：cutlist items 为扁平结构，每子段一条 item，`sub` 是计数而非子段列表——扫描脚本首次误判「无多保留段」，dump 键结构后纠正。）

## 修复（cd701d3）

| 改动 | 说明 |
|---|---|
| **索引跟踪** `cutKeepIdx` | 只看当前 keep 段、只前进不回扫；播过当前段尾 → seek 下一段起点；播完最后一段 → 暂停收起。一次到底，结构上不可能乒乓 |
| **回拖重定位** | 用户拖进度条回拖 >500ms → 重定位到 tms 所在段，跳播从该段继续 |
| **试听条** `.slirn-cut-audition` | 「🎧 试听（成片口径）0:02 / 0:04 · 保留段 2/3 · 对应视频 0:22」——成片时间 = 已播 keep 段累计 + 段内偏移，连续不回退；同时给出对应视频原始时间做映射。跳播下视频原生时间戳必跳变，这条时间轴与试听进度严格一致 |
| **重渲染清零** | openWorkbench 重渲染后 `cutKeepSeq/cutStopAt/cutKeepIdx` 清零（旧行引用失效防野指针） |
| **退出路径收条** | 手动暂停 / 行预播 / 播放完毕 三处收起试听条 |
