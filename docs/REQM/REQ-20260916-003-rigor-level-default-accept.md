## 1. 需求（用户原话转述）

> 把决策列中的内容默认都选为采纳建议。
> 然后针对通过大模型分析字幕时，要设置一个参数，这个参数是用户必须选的，就是
> 对字幕分析严谨性的级别，分为高、中、低。例如现在执行过这次分析，我觉得分析得
> 非常好，就是要求是比较高的，然后再加一个中等级和低等级的，中等级的只要字幕
> 这句话表达的意思是正确的，没有太大的瑕疵就行，低一等级的允许字幕内容有部分
> 瑕疵，但不能有过多的重复或者意思混乱的句子。
> 然后操作者在选择这个参数时，要给这3个参数更加准确的一个描述说明，让他知道
> 这3个不同等级大概是什么样子的。例如例子，让使用者有了大体上的体感感受。

两个诉求：
1. **决策列默认「采纳建议」**：扫描改掉不同意的行，直接保存即全量采纳。
2. **严谨性级别必选**（高/中/低）：级别注入大模型提示词决定挑毛病的严格程度；
   选择界面要带准确描述 + 例子，让操作者有体感。当前线上效果即「高」档。

## 2. 设计

### 2.1 决策列默认「采纳建议」

- 渲染层：未决策（pending）行 select 默认选中 `accept`；已保存的决策照旧回填。
  「未决策」选项保留，可手动改回。
- 统计口径不变：已决策 X/N 仍按**已保存**数据计算 — 默认值保存后才生效，
  统计行加提示「决策列默认『采纳建议』」。
- 保存/合并逻辑（save_revision / merge_decisions）零改动。

### 2.2 严谨性级别（RIGOR_LEVELS）

| key | 标题 | 判定尺度（注入提示词） | 适用 |
|---|---|---|---|
| high | 高 · 严格打磨 | 以成品口播稿标准逐句精修：语气词、口癖、重复、寒暄全处理（= 原判定标准） | 对外发布成片 |
| medium | 中 · 意思正确即可 | 只处理影响理解的问题：明显口误、连续重复、明显不通顺小幅修剪；小语气词容忍保留 | 内部学习/速览 |
| low | 低 · 只去严重问题 | 最大限度保留原文：只处理大段纯重复和意思混乱句子；语气词、轻微口误保留 | 只要大意、尽快出片 |

- `revision_service.RIGOR_LEVELS`：每档含 prompt 侧（badge/title/stance/criteria）
  与 UI 侧（desc/example）元数据；`build_system_prompt(rigor)` 组装系统提示词
  （未知级别防御性回退 high）。
- `start_job(..., rigor)`：非法级别直接 ValueError（不发请求）；级别写入
  revision.json meta `rigor` 留痕；统计行显示 `· 严谨性 高（严格打磨）`
  （旧数据无 rigor 不显示，向后兼容）。

### 2.3 选择界面（必选 + 体感说明）

- **状态 2**（无建议）：分析按钮上方渲染三张单选卡 — 标题 / 一句定位说明 /
  **「例：…」**例子行（如高档「嗯呃，那个，就是说，我们今天讲一下神经网络」→
  修剪为「我们今天讲一下神经网络」）。服务端**不预选**，用户必须主动选。
- **状态 3**（重新分析）：同样三张卡收进 `<details>` 折叠框，不占日常视线。
- 前端拦截：未选级别点「分析/重新分析」→ toast 报错 + 自动展开折叠框滚动到位，
  **不发请求**；级别检查先于覆盖确认弹窗。
- 服务端兜底：`/revise_subtitle` 校验 `rigor ∈ {high,medium,low}`，缺失/非法
  一律拒绝（API 直调也无法绕过）。
- 记忆：选中级别存 localStorage `slirnRevRigor`，重开工作台预填上次选择
  （仍可在界面上改；第一次使用必须显式选择）。
