## 0. 背景

任务详情页（view_task）当前回显的信息与「新建任务」时的展示不一致、不完整：
原始视频只显示裸路径（无文件名/大小/时长格式），热词截断为"前 8 个"纯文本
（新建时是带来源标签的 chips 全量展示），且热词来源（继承公共库/勾选/手动）
在创建时合并后即丢失，无法还原。

用户要求：任务应可回显任务信息，**内容与显示方式与新建任务时保持一致**，
**所有信息都还原出来**。

## 1. 核心需求

| ID | 需求 |
|---|---|
| REQ-2.1 | 详情页回显原视频信息，格式与新建步骤 1 文件信息条一致：`📁 {文件名}（{size} MB · {HH:MM:SS}）`；同时保留完整路径；文件缺失/时长探测失败时降级标注，不报错 |
| REQ-2.2 | 回显截取段：起止时间（用户输入原样，含毫秒）+ 截取段时长 + 截取文件大小（MB），显示方式对齐新建时「✅ 截取成功 {size} MB」；无截取段明示「未截取 · 使用完整原视频」 |
| REQ-2.3 | 热词以 chips **全量**回显（不截断），带来源标签（继承/已选/手动），底部汇总 `共 N 个词`（勾了继承时附 `· 来自继承全部公共库`）— 与新建步骤 3「最终生效的热词」显示方式一致；回显只读（无 ✕ 移除按钮） |
| REQ-2.4 | 创建任务时持久化热词来源：`inherit_public`（是否勾选继承全部）+ `hotword_sources`（word → inherit/pick/manual）写入 metadata.json；**旧任务无此数据 → 降级为无标签纯 chips**（向后兼容，schema_version 仍为 1，可选字段不破坏旧读写） |
| REQ-2.5 | 既有详情信息（任务名/状态/任务 ID/创建·修改时间/删除按钮/字幕区）全部保留不动 |

- [x] AC-1 新建任务（含继承/勾选/手动三种来源）→ 详情页热词区 chips 全量展示，来源标签正确，汇总行含「来自继承全部公共库」
- [x] AC-2 详情页原视频行格式 = `📁 {name}（{size} MB · {duration}）`，与新建步骤 1 的文件信息条逐字符同格式
- [x] AC-3 截取段行展示原样起止时间 + 时长 + MB；无截取段任务明示「未截取」
- [x] AC-4 旧任务（无 hotword_sources，如 REQ-20260915-001 的 20260915-004）详情页正常渲染为无标签 chips，不报错
- [x] AC-5 原视频文件被移走后详情页仍可打开，视频行降级标注「文件缺失」

- [x] AC-7 浏览器实测：详情页视觉与新建页 chips/文件信息条一致
