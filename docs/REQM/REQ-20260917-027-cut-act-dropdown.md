# REQ-20260917-027 — 切分修剪组级决策下拉 + 选中不被跳播抢走

## 需求原话

> 在切分修剪阶段，右边的决策状态在鼠标点击的时候需要显示下拉列表，并可以
> 选择改变为某个状态。而现在是使用快捷键删除了该条字幕后，就无法处于选中
> 状态了

## 根因与设计

### 1. 决策状态只能键盘改

组级决策徽章（`data-abadge` span「维持原状 / ✅ 已改判保留 / …」）是纯
展示，改判只有快捷键 K/D/S 一条路。

**改法**：徽章位置改为**原生 `<select class="slirn-cut-abadge slirn-cut-actsel">`**，
四个选项：维持原状 / ✅ 改判保留 / ❌ 改判删除 / ✂️ 改判切分。沿用徽章
配色（组 `data-act` 上色规则不变，`option` 显式深色字防白底白字），保留
原生下拉箭头。切分组组头与整段行两处同改。

- 核心逻辑抽 `cutApplyAct(g, val)`：置/清组 `data-act` + 同步下拉值 +
  split 展开重切编辑区 + toast——**下拉与 K/D/S 完全同效**
- 下拉选「维持原状」= 取消改判；选回当前值 = 无操作（键盘保留「再按
  同键取消」语义）
- 行点击处理器排除 `select`（点下拉只开下拉，不触发选行预播）

### 2. 快捷键删除后行「无法选中」

`bindCutPlayer` 的 timeupdate 在跳播下一段时执行 `cutMarkSel(nxt.row)`——
kbsel 是**决策目标**却被播放跟随抢走：点已删除的行 → 播放从后面的保留段
开始 → 播段一切走 kbsel 即被拖离，用户无法再对该行按 K/D/S 或感知选中。

**改法**：删掉这行。播放位置高亮本就由 ② 的 `.active` 独立跟随
（`rows[j].toggle('active', j === hit)`），kbsel 回归纯决策目标——点哪行
选中就停在哪行（含已删除的行），立即可用下拉/快捷键改回。与字幕修订面板
（setActive 跟播放、kbsel 归键盘）同构。
