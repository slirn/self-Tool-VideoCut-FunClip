## 0. 与上游 REQ 的关系

- REQ-A 已实现 `TaskManager.create(..., hotwords=...)` 参数 + `tasks/<id>/hotwords.txt` 落盘（**任务级热词**）
- REQ-C 已实现"任务级热词手动输入"入口（**`hotwords_box` Textbox**）
- 本 REQ 实现"公共热词库"——**项目级**共享 + **任务级**复用：用户可从库中挑选加入本任务

**关键区别**：
- **任务级**（REQ-C）：写在 `tasks/<id>/hotwords.txt`，随任务走
- **公共级**（本 REQ）：写在 `hotwords/public.txt`（仓库根），所有任务共享

---

## 1. 背景与目标

**当前状态**：用户每次新建任务都要手动输入热词（FunASR 张老师、达摩院等），重复劳动。

**目标**：建立项目级公共热词库：
1. 用户可增/删/改热词
2. 新建任务时从库中**多选**加入本任务
3. **分类支持**：按场景分组（如"讲师"/"专业术语"/"产品名"）
4. **搜索 + 分页**：>50 个热词时易找

**价值**：把"每次新建任务都重输热词"变成"一次性维护 + 复用"。

---

## 2. 用户故事

### US-D1：维护公共热词（添加）

- **角色**：项目使用者
- **场景**：发现一个反复出现的人名/术语
- **操作**：进「热词库管理」tab → 输入词 + 选分类 → 点「添加」
- **结果**：词入库，下次选择面板可见

### US-D2：从库中选热词加入任务

- **角色**：同上
- **场景**：新建任务时想让 FunASR 识别人名
- **操作**：「新建任务」tab → 点「从公共库选择」 → 5×10 网格中点选「张老师」「达摩院」 → 自动填入本任务的热词框
- **结果**：选中词进入本任务 hotwords.txt

### US-D3：搜索热词

- **角色**：同上
- **场景**：库里有 200 个词，要找"FunASR"
- **操作**：在搜索框输「FunASR」 → 网格过滤显示
- **结果**：仅显示含 FunASR 的词

### US-D4：分类管理

- **角色**：同上
- **场景**：想给现有词归类（讲师/术语）
- **操作**：词管理界面 → 改某词的分类 → 保存
- **结果**：分类立即生效

## 6. 技术约束

- **存储**：纯文件（`hotwords/public.txt` + `hotwords/categories.json`），与任务数据一致原则
- **API**：在 `slirn-standalone/tasklib/hotword_lib.py`（与 `tasklib/video.py` 同级）
- **UI**：在 `funclip-main/slirn_home/hotword_ui.py`，**不引入新依赖**
- **Gradio 组件**：`gr.Dataframe`（分组展示）、`gr.CheckboxGroup`（多选）、`gr.Textbox`（搜索/输入）、`gr.Button`、`gr.Accordion`
- **去重**：基于 `set` + `list` 保持插入顺序

---

## 7. 反例

- ❌ 分类嵌套（仅一层分类）
- ❌ 公共库和任务级热词耦合存储（必须分开文件）
- ❌ 维护 UI 必须重启服务才能看到新词
- ❌ 选择 UI 一行 N 个词自适应（必须 5 列固定网格）
- ❌ 选中后无法取消（必须有「清空选择」）
