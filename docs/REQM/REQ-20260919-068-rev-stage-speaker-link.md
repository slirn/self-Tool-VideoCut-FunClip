# REQ-20260919-068 字幕修订阶段·人员 ID 关联

## 背景

切分修剪阶段（REQ-20260917-031/033）已经做了「关联人员ID」功能：按时间段重叠把 subtitle 段级 spk 对齐到切分清单每行，按人员统计未删除记录数，提供 chips/查找/跳转/删除/重算。

用户反馈：「字幕修订阶段也要同样的功能」。修订阶段也有大量记录（数十~数百段），按说话人统计、按说话人跳转、按说话人批量删除（识别非主讲人员时很有用）能极大提升效率。

## 验收标准

| ID | 验收项 |
|---|---|
| AC-1 | 字幕修订面板行内显示人员徽章（紧跟序号，与切分修剪一致的位置/样式） |
| AC-2 | 字幕修订面板顶部新增「关联人员ID / 重新关联人员ID」按钮（在保存决策按钮附近） |
| AC-3 | 关联成功后渲染「👥 人员统计」条：chips（每个 spk + count）+ 查找输入框 + 上一条/下一条 + 删除该人员全部记录 + 重新统计 |
| AC-4 | 人员徽章 / 统计条 / chips 都由后端现算（不读快照），快照仅供人工检查 |
| AC-5 | 关联状态落盘 `outputs/rev_speaker_link.json`（version=1, enabled, linked_at, rows, stats）；重进任务时面板自动显示 |
| AC-6 | chips 点击 → 填入查找框（与切分修剪一致） |
| AC-7 | 「按人员ID查找」+「上一条/下一条」只在当前 spk 的未删除记录间跳转 |
| AC-8 | 「跳过已删除」checkbox 控制导航是否跳过删除决策行 |
| AC-9 | 「删除该人员全部记录」一键把所有当前 spk 的行决策设为 `delete`（需前端确认） |
| AC-10 | 「重新统计」按钮重新拉后端（不重新关联 — 对齐确定性，修订实时变化无需重算链接） |
| AC-11 | 单测：rev_speaker.link_speakers 给定 mock subtitle + revision 返回正确 rows/stats；rev_speaker_link endpoint 路径 |

## 不做的事

- ❌ 不改动切分修剪阶段的人员功能（保持原样）
- ❌ 不在修订阶段做"删除改判需落盘"的强校验（修订阶段决策改了就生效到 revision.json，无需额外保存步骤）
- ❌ 不修改 revision_service 的字段（行级 spk 由前端从 `data-spk` 属性读取，不入 revision.json）
- ❌ 不修改 subtitle.json 本身（人员编号来自字幕生成阶段的 spk 字段）
- ❌ 不为旧任务做迁移（speaker_link.json 无则不显示关联功能）
