# REQ-20260917-025 — 状态跳转改独立状态下拉（v2）

## 需求原话

> 在上一条、下一条按钮的前边加一个状态选择列表。在这个情况下所跳转时，
> 整个字幕还是显示的，只是跳转到指定状态的某条记录上。如果直接点状态
> 过滤的话，就看不到某个状态前后的相关上下文字母，不利于对整个内容
> 连贯性的理解

## 设计（对 REQ-20260917-024 的修正）

v1（REQ-024）跳转目标**跟随筛选 chip**——用户要先点状态 chip 再跳，语义
纠缠；v2 把跳转目标改为**按钮前的独立状态下拉**，与筛选完全解耦：

| 维度 | 筛选 chips（不变） | 状态下拉 + ⬆/⬇（v2） |
|---|---|---|
| 目的 | 视图收窄（只看某状态） | **上下文导航**（全列表常显，定位到该状态记录） |
| 藏行 | 是 | **否**——跳转时强制显示全部行 |
| 状态来源 | 点击 chip | 下拉显式选择（localStorage `slirnRevJump` 持久化） |

- 下拉两组 optgroup：**建议状态**（全部/保留/删除/切分/更正/复核）、
  **决策状态**（全部/未决策/采纳建议/保留/删除/切分/内容更正），
  值形如 `dec:pending`；默认 `决策 · 未决策`（评审主循环的自然目标）
- 匹配口径与筛选**完全同源**：新抽参数化匹配器 `revMatchKind(row, dim, val)`
  （sugg 比 `data-sugg`；pending/accept 比 `data-decision`；其余比
  `data-final` 实质类别），`revFilterMatch` / `revFilterCountOf` 改为委托
  ——三处逻辑合一，杜绝口径漂移
- 跳转行为不变（继承 REQ-024）：全列表常显 + `kbsel` 高亮 + 居中滚动 +
  播放器定位 + 循环 toast + `跳转「决策 · 删除」3/5 · 显示全部 N 条` 计数
- 换下拉值 → 跳转锚点 `revJumpIdx` 重置；点筛选 chip **不再**触碰跳转
  锚点（彻底解耦，锚点跨筛选操作保留）
- 纯前端改动：+60 行 JS / -10 行（去 v1 耦合）/ 10 行 CSS / 4 行 HTML；
  无新端点、无新依赖
