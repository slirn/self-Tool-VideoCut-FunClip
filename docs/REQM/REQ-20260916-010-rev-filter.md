# REQ-20260916-010 — split 建议自动预填切分修剪后内容 + 修订列表状态过滤

## 需求原话

> 凡是需要切分修剪的，在大模型进行字幕修订分析时，自动提供修剪后的文字内容，填写到切分修剪后内容区域中。在字幕修订区域上边添加一个状态过滤功能，可以过滤不同建议状态或决策状态的字幕，查询决策状态时，如果决策状态是采纳建议的话，其实质还是过滤建议状态

## 设计

### ① split 自动预填「切分修剪后内容」

双层实现，新分析 + 存量任务都生效：

- **分析落盘时**（revision_service.start_job）：构造 entries 时 split 行 `user_note = keep_text`（建议的修剪后文本）——需求原话「在大模型进行字幕修订分析时，自动提供」。重新分析本就重置全部决策，覆盖旧值语义一致。
- **渲染层兜底**（`_render_revision_zone`）：`user_note` 为空的 split 行预填 `keep_text` 作 input 初始值——存量任务（未重分析）也能直接看到/微调将要生效的修剪后内容。
- 优先级：**手动填写 > 建议文本**；用户清空保存 → 切分清单回退 keep_text（cutlist_service `_split_target` 既有逻辑），语义自洽。fix 行不预填（需求只提切分；更正文本已在详情块「✏️ 更正后」展示）。
- `open_detail` 判定仍用存储的 user_note（预填不导致 split 行全部自动展开）。

### ② 状态过滤条（列表上方）

- 结构：`🔎 筛选` + 维度切换（**建议状态 / 决策状态** 胶囊）+ 筛选 chips（带实时计数）+ `显示 X / N 条`。
- **建议维度**：全部 / 保留 / 删除 / 切分 / 更正 / 复核（按行 `data-sugg`）。
- **决策维度**：全部 / 未决策 / 采纳建议（按 `data-decision`）/ 保留 / 删除 / 切分 / 内容更正 —— 后四者按**实质类别** `data-final` 匹配（用户原话「决策状态是采纳建议的话，其实质还是过滤建议状态」）：**accept 的实质 = 模型建议类别**，与 cutlist_service `_final_kind` 同源 —— 筛「切分」时「采纳+建议切分」的行也命中。
- 行携带 `data-sugg` / `data-decision` / `data-final`（服务端渲染时算好；实质类别 = 手动改判优先 → accept 取建议类别 → pending 空）。
- **决策下拉变化即时联动**：change 事件更新行 data 属性 → chips 计数 + 可见性实时刷新（未保存前纯前端，刷新即还原服务端状态）。
- 筛选只藏行不删行：**「保存修订决策」仍收集全部行**（revRows 不受过滤影响，未决策行默认 accept 必须全部落盘）；快捷键（↑↓/空格/R/K/D/S）与鼠标选中只走可见行（新 `revNavRows()`）。
- 筛选状态存 localStorage（slirnRevFilter）；`switchWbPane` 切面板后重算计数（工作台初始打开时修订面板可能隐藏，revRows 取不到行）。
- chips 带 title 提示「实质口径：含「采纳建议」且建议为此类的行」。

## 验收标准

1. 大模型分析完成后，需要切分修剪（split）的行「切分修剪后内容」输入区已自动填入建议的修剪后文字。✅
2. 手动修改过的内容不被建议文本覆盖。✅
3. 修订区域上方有状态过滤：可按建议状态（保留/删除/切分/更正/复核）过滤。✅
4. 可按决策状态过滤；「采纳建议」的行按其实质（=建议状态）归入对应类别。✅
5. 每个筛选项带计数；筛选后显示「X / N 条」；改决策后计数/可见性实时刷新。✅
6. 筛选不影响保存：全部行（含被筛掉的）仍随「保存修订决策」提交。✅
7. 快捷键导航跳过被筛掉的行。✅
