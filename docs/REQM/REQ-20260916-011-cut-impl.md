# REQ-20260916-011（实施）— 切分修剪完整时间轴划分与四级调整

设计文档（`docs/design/DESIGN-20260916-011-split-pruning.md`）的 M1-M4 全量实施。前置 bug 修复与设计文档见 [REQ-20260916-011-stages-rail.md](REQ-20260916-011-stages-rail.md)。

## 需求原话（四轮补充）

> 切分时间戳是根据视频提取的吗？是的话要加预览功能——播放截取后的视频片段确认切分效果，参考字幕修订的播放效果；还要能针对选中的原片段重新填写切分后内容，进行单片重新切分。
>
> 切分修剪阶段还需要一个重新执行切分修剪的功能。
>
> 预览时视频中音频对应的字幕要高亮；把字幕修订的上一句/下一句/播放暂停快捷键带过来；单条字幕的重新切分入口（可修改切分后文字，一条切多段，同样可预览）。
>
> 快捷键把删除和保留也带回来——哪句话不需要可以删除，有决策状态：决策为空保持原样，变化了按决策执行（完整保留的也可能改切分或删除）。判断是否把修订阶段所有快捷键都带过来。

## 交付：四级调整体系

| 级别 | 操作 | 生效粒度 | 落点 |
|---|---|---|---|
| L1 翻转标记 | 点子段徽章 | 子段去留 | manual_marks `父.子` |
| L2 字幕级改判 | K/D/S | 整条字幕决策 | actions `str(source_i)` |
| L3 单段重切 | ✂️ 行内编辑 | 单父段重新划分 | 修订 user_note（单一事实源） |
| L4 重新执行 | 🔄 按钮 | 整单重算 | 清空全部手工决策后 build |

决策优先级：L2 > L1 > 建议；L4 清空 L1/L2/L3 后回到建议。

## 实施（M1-M4）

### M1 算法层（cutlist_service.py）

- `partition_tokens(n_tokens, keep_marks)`：keep 块与 delete 洞交替覆盖 `[0,n)`，不重不漏；**父.N 时间序编号与标记解耦**（翻转只改 mark，不动编号）。
- delete 洞时间边界**外扩**：`s=prev_e`、`e=下一 keep 块首 token 起`（无则父段终点），相邻 token 无缝的零长洞不产段（`e-s<=0` 跳过）——父段时间轴完全二分，无帧残留缝隙。
- `build_cutlist` v2：`decision ∈ keep/delete/split/fix` 优先于建议 category；`action=="keep" and kind=="split"` → 归一整段条目（改判保留则子段划分作废）；`kind is None` 防御按 keep 带入；stats 补 split_parents/split_subs_delete/mark_flipped/fallback 等计数；`keep_duration_ms` 按 effective_keep_units 执行口径。
- `effective_keep_units`：整条 delete 剔除、split 子段 mark=delete 剔除。
- `resplit_segment(subtitle_meta, revision, source_i, target_text)`：校验链（空内容/非法 source_i/找不到条目/**无字级时间戳**明确报错提示去字幕生成阶段重生成/**命中 0 字宁可不切**）→ 成功置 `decision="split"`、`user_note=target[:500]`、清该父段 manual_marks/actions，重建清单。

### M2 分组渲染与预播（app.py + home.css）

- 切分组：组头（父编号 + 切分修剪徽章 + 原段「…」→ 切分后文字 + 决策徽章 + ✂️ 重新切分 + ▶ 试听）+ 子段行（标记徽章可点翻转，翻删除加删除线）。
- **整段组单行化**（实施决策）：整段条目也渲染 `.slirn-cut-row.whole` 单行，`cutRows()` 统一覆盖 whole+sub → 键盘导航/预播/高亮/改判对两类行行为一致。
- 预播：行点击/空格 → `currentTime` seek 行起点，`timeupdate` 三合一（keep 连续跳播 / 段尾自动停 / `.playing` 高亮 + scrollIntoView）；组头 ▶ 试听 = keep 子段连续跳播。
- 快捷键（切分区可见时接管，与修订区互不抢键）：↑↓ 导航 / 空格播放暂停 / R 重播；`e.repeat` 只放行 prev/next。
- 保存切分决策端点（`save_cut_decisions`）+ 状态化主按钮（有清单→「🔄 重新执行切分修剪」+ confirm 清除提示；无→「⚙️ 生成切分清单」）+ 修订更新于清单之后的**过期黄条**。

### M3 字幕级改判与单段重切

- K/D/S：作用于选中行所属组，组 `data-act` + 决策徽章（✅ 已改判保留 / ❌ 已改判删除 / ✂️ 已改判切分）+ 子段置灰禁点（`pointer-events:none`）；**再按同键取消**还原。
- ✂️ 重切：组内行内编辑区展开、预填 `data-target||data-orig-text`（focus+全选），确认 → `resplit_segment` 端点；Esc 关闭（输入框焦点判定优先）。
- **split_targets 双路径闭环**（实施决策）：S→填内容→直接保存 也回写修订 user_note（保存路径携带 split_targets），与重切路径汇合到同一事实源。

### M4 验证（见下）+ 服务重启

## 实施决策记录

1. **resplit 后 `openWorkbench` 全刷新**而非局部重渲染：清单由服务端重建（fallback/统计/黄条联动），局部更新需复制服务端逻辑，收益低风险高。
2. **saved_at 落盘顺序**：任何「修订+清单」双写端点，revision.json 先写（T1）、cutlist.json 后写（T2≥T1）→ 黄条 `rev_at > cut_at` 恒 false，无误报。
3. **整段组单行化**（见 M2）：初版整段组=纯组头无行，键盘/改判无法选中 → 重构。
4. **改判置灰而非隐藏**：保留视觉锚点（原建议仍可见），opacity .4 + 禁点。
5. **宁可不切不可错切**：重切对齐命中 0 字直接报错，不猜。
