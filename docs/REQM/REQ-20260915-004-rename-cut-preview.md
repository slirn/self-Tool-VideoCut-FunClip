## 0. 背景

用户澄清概念：上传的**原始视频并不是真正要处理的素材**，「截取」动作的产物才是
进入后续剪辑管线的对象 — 即从原始视频中截取出**需要进一步剪辑的视频**。
因此新建任务页的「截取预览」命名不准确，应更名为「**待剪辑视频预览**」。

## 1. 核心需求

| ID | 需求 |
|---|---|
| REQ-4.1 | 新建任务页步骤 2 的按钮 `🎬 截取预览` 更名为 `🎬 待剪辑视频预览`（全新建 + 编辑模式同一套页面，两处都改） |
| REQ-4.2 | 该动作的完成反馈同步更名：JS 状态消息与服务端 toast `✅ 截取成功 N MB` → `✅ 待剪辑视频已生成 N MB` |
| REQ-4.3 | 内部标识符（`data-action="cut-preview"`、`/slirn/api/cut_preview`、`slirn-cut-preview` 元素 id、tasklib `cut_video`）**不改** — 纯文案变更，避免波及 API/测试 |

## 2. 验收标准

- [ ] AC-1 新建页（全新建 + 编辑模式）渲染 `🎬 待剪辑视频预览` 按钮，且不再出现「截取预览」字样
- [ ] AC-2 截取完成反馈为「✅ 待剪辑视频已生成 N MB」（JS 消息 + 服务端 toast 一致）
- [ ] AC-3 任务详情/工作台等其余页面的「截取段」术语不变（本次范围外）
- [ ] AC-4 pytest 全过 + ruff 0 错
