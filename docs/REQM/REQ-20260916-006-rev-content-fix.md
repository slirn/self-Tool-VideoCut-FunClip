## 1. 需求（用户原话）

> 在字幕修订阶段再添加一个状态，叫内容更正，就是在大模型进行字幕分析的过程中，
> 如果发现字幕文字是有错字、别字等这些文字上的差异时，直接把字幕内容修订为正确的内容，
> 并在说明中记录在字幕生成阶段生成的有误的文字进行对照说明。
> 另外，把手动处理说明的可输入区域改为切分修剪后内容。

## 2. 设计

### 2.1 新类别 `fix`（内容更正）

- **模型建议类别** 4 → 5：keep / delete / split / **fix** / review；手动决策下拉同步新增
  「内容更正」（可手动改判，如模型判 keep 但用户发现错字）。
- **提示词**（`FIX_CRITERIA`，注入所有严谨性级别）：错字/别字/同音字误识别等**文字错误**
  → `category="fix"`，`keep_text` 给出**更正后的完整字幕文本**（即"直接把字幕内容修订
  为正确的内容"——模型直接给出成品文本而非仅标记），`note` 给出**原文与更正的对照说明**
  （原文哪个字有误、应更正为什么）。**与严谨性级别无关**——文字对错是事实问题，
  任何级别都必须判；边界：说话人本身口误/需修剪语义 ≠ 文字错误，仍走其余类别。
- **解析防御**：fix 但 `keep_text` 缺失/空白 → 更正无从执行，降级 review，note 前缀
  「模型发现文字错误但未给出更正文本，请人工修改：」保留模型发现的问题。
- **兼容**：旧 revision.json（无 fix）原样渲染；meta `version` 仍为 1（新增类别枚举向后兼容）。

### 2.2 UI

- 徽章 🟦 内容更正（`#2563eb` 蓝，区别于切分紫）；详情块新增
  `✏️ 更正后：「…」`（蓝色，与切分的 `✂️ 建议保留` 平行，复用 keeptext 样式加 `.fix` 变体）。
- 未决策默认「采纳建议」（REQ-003 不回归）——fix 行采纳即采用更正文本。
- 统计行新增 `更正 N` 计数；状态2 介绍新增 🟦 内容更正一行。
- fix 行与 split 一致**不默认展开**（模型已给出目标文本，列表保持紧凑；点 ▾ 看 对照+更正后）。

### 2.3 输入区改名

`手动处理说明（可空）` → **`切分修剪后内容（可空）`**（用户原话）。数据字段仍为
`user_note`（已有数据无损）；配套文案同步：切分 toast「填写切分修剪后内容后按 Esc 返回」、
提示条「S 切分（展开详情聚焦内容）」、展开钮 title、统计行「▾ 展开模型分析与切分修剪后内容」。
