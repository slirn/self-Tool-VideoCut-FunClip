# REQ-20260916-014 — 播放器倍速显示与控制

## 需求原话

> 现在有一个bug，不知道为什么什么快捷键导致了在按照字幕文件播放时，音频文件的播放速度有时会加快，有时会变慢，所以这时需要有一个倍速的显示信息，可以看到当前的播放速度，并且可以把速度调大或调小，以及调回原来的值，这样更能够方便使用该软件的人按照自己的速度进行。查看编辑效果

## 诊断

grep 全部代码（app.py + static/）：**`playbackRate` / `ratechange` / `preservesPitch` 零命中**——我们的快捷键和代码从不改变播放速度。神秘变速来自外部途径，最可能是 **Chrome 原生视频控件的播放速度菜单**（视频上右键 →「播放速度」，或控制条 ⋮ 菜单），用户误点而不自知；页面上原本没有任何倍速显示，变速就成了"不知道为什么变快变慢"的黑盒。

**根治手段不是禁用，而是让速率可见**：加倍速显示 + 主动调节 + `ratechange` 事件监听——无论速率被什么途径改掉（原生菜单/浏览器扩展/本控件），显示永远反映真实值。

## 实现（2bab78a）

| 改动 | 说明 |
|---|---|
| `bindSpeedControl(v)` | 向播放器 `.slirn-video-wrap` 注入 `[−] [当前倍速] [＋]` 控件（幂等，元素已存在则只重应用速率） |
| 阶梯调节 | `[0.5, 0.75, 1, 1.25, 1.5, 1.75, 2, 2.5, 3]`；− / ＋ 沿阶梯上下移一格，边界夹紧（min 0.5 / max 3）；当前速率不在阶梯上时按最近档位吸附再移动 |
| 一键回原速 | 点中间速率标签 = 恢复 1x（"调回原来的值"） |
| `ratechange` 监听 | 任何来源的变速同步到显示——外部改了速率，标签立刻如实显示 |
| 会话级 `slirnRate` | 播放器元素随面板重渲染重建（浏览器重置为 1x），重绑时自动把会话倍速应用回去；跨三阶段、跨重开工作台一致 |
| 全覆盖装配点 | `bindSubPlayer` / `bindRevPlayer` / `bindCutPlayer`（三个编辑阶段）+ `initTaskEdit` / `applyFileInfo` / `applyCutDone`（任务详情页、新建任务、成片预览）共 6 处 |
| CSS `.slirn-speed` | 紫系 pill 按钮排（复用 `.slirn-btn-xs`），速率标签等宽字体 `min-width:46px`（"0.75x" 不换行），与试听条同风格 |

## 验证

- `pytest tests/ -q` → **162 passed**；`ruff check .` → clean。
- **E2E 只读**（CDP headless，20260915-002，`work/REQ-20260916-014-speed/_speed_test.py`）九项全过：
  - ① 三个阶段播放器 wrap 都注入 `.slirn-speed`（隐藏阶段也在 DOM，openWorkbench 即注入）
  - ② 初始显示 `1x` 且 `video.playbackRate == 1`
  - ③ ＋×2 → 1.5x；− → 1.25x；−×5 夹紧 0.5x；＋×10 夹紧 3x（标签与真实速率每步同步断言）
  - ④ 点中间标签 → 恢复 1x
  - ⑤ **外部变速**（直接设 `video.playbackRate=2`，模拟 Chrome 原生菜单/扩展）→ 标签同步显示 2x；设非阶梯 1.3 再 ＋ → 吸附到 1.5x
  - ⑥ 设 1.5x → 回任务列表 → 重开工作台（元素重建）→ 自动恢复 1.5x
  - ⑦ 任务详情页播放器（edit-task → initTaskEdit）有控件并继承会话倍速
  - ⑧ 截图存档 `_shot_speed.png`；⑨ **零写请求**（api 仅 workbench/edit_task/video）
- **DOM 几何复核**：控件 20px 高、视频下方 8px 无叠压、容器宽度内、速率标签 46px 等宽字体、页面无横向溢出。
