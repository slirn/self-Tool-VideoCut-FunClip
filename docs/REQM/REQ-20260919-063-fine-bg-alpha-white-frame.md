# REQ-20260919-063 精剪视频·bg 图 RGBA alpha 透明区误显示白色（"白框"真凶）

## 背景

用户多次报告精剪视频预览有"白框"，尝试改字幕 bg_enabled、bg_opacity、字幕字体颜色都没用（REQ-20260919-062 已修字体颜色但仍未解决）。

**真正的根因**：

用户的 bg 图（`bg_长视频背景_第五课.png`）是 **RGBA** 格式，左下角视频区是 alpha=0（完全透明）：

| 位置 | RGB | Alpha |
|---|---|---|
| 左下 x=10%, y=80% | (255, 255, 255) | **0** |
| 左下 x=50%, y=95% | (255, 255, 255) | **0** |
| 右下 x=85%, y=85% | (1, 2, 2) | 255 |

但 ffmpeg filter chain 直接用 `[bg:v]scale=W:H,setsar=1[bg]` —— **没有黑底 + 没处理 alpha**。结果：
- 透明像素的 RGB (255,255,255) 被当成实际颜色渲染 → 用户看到白色
- 视频覆盖不到的地方（左下角 175px = 1920x1080 设计空间 y=905 之下）= 白色 bg 图透出

`fc.layout.video.scale=0.828, crop_h=990, y=85` → 视频底部 y = 85 + 990×0.828 ≈ 905。下方 175px 全是 bg 图透明区 = 白框。

## 验收标准

| ID | 验收项 |
|---|---|
| AC-1 | bg 图透明区在最终输出里显示**黑色**（用户预期：视频覆盖不到的地方是黑底） |
| AC-2 | bg 图不透明区照常显示（深色 header/footer/右栏 不变） |
| AC-3 | 视频覆盖区照常显示 slide 内容 |
| AC-4 | cover（前 2s） + 字幕 burn-in 不受影响 |
| AC-5 | 用户禁用 bg layer 时，行为不变（继续走 black canvas 默认） |
| AC-6 | 单元测试：filter chain 包含 `[bg_b][bg_img]overlay...` 模式；E2E 像素采样确认 y=1000 是黑色 |
| AC-7 | 不破坏 REQ-20260919-062 的字体颜色修复 |

## 不做的事

- ❌ 不动 bg 图本身（用户上传的素材不能改）
- ❌ 不强制 bg 图转 RGB（保留 alpha，透明处合理显示黑底）
- ❌ 不动 cover 渲染（cover 已是不透明 PNG，不受此 bug 影响）
- ❌ 不引入新的 ffmpeg 选项（用标准 `format=auto` + 黑底 overlay）
