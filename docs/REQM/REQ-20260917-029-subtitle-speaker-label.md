## 0. 背景

任务详情页「处理剪辑 · 第 1 步：生成字幕」目前只输出不带说话人信息的字幕。
课程视频多为多人对话（讲师 + 学员 / 双讲师），需要在生成字幕时同时分辨
每段文字是哪个人说的，并统计每个人说了多少句。

上游 FunClip 的识别链路本身支持说话人分离（FunASR cam++ 声纹模型，
`VideoClipper.recog(sd_switch='Yes')` 返回逐句 `spk` 标签），本需求把它接入
slirn_home 字幕生成阶段，不改 `funclip/` 上游源码。

## 1. 核心需求

| ID | 需求 |
|---|---|
| REQ-1.1 | 生成字幕时默认开启说话人分离：识别结果逐句带说话人标签（FunASR cam++） |
| REQ-1.2 | 每个说话人分配一个**人员编号**（1 起始、按首次出现顺序），字幕段携带该编号 |
| REQ-1.3 | `subtitle.json`：每段增加 `spk` 字段（人员编号，int）；meta 增加 `speakers` 统计（人数 + 每人句数） |
| REQ-1.4 | `subtitle.srt`：每段序号行携带 `spk{N}` 标签（与 json/UI 编号一致），块间标准空行分隔 |
| REQ-1.5 | 生成完成后 UI 呈现：字幕列表每行显示「人员N」彩色徽标；列表上方显示每人句数统计 |
| REQ-1.6 | 生成完成后服务端日志输出每人句数统计 |
| REQ-1.7 | 提供「区分说话人」开关（默认开）；关闭时行为与现状一致（无编号、无统计） |
| REQ-1.8 | 旧任务兼容：已存在的无 `spk` 字段的 subtitle.json 渲染与统计均不回归 |

## 4. 统计口径

- 「一句话」= 识别断句后的一个字幕段（长句被 `_split_long_sentence`
  拆分后，每个字幕行计 1 句，与 UI 列表行数一致）。
- 单说话人视频正常情况下只有 人员1；cam++ 偶发把同一人分裂为多簇，
  属模型局限，靠统计行目视发现，人工可选择关闭开关重新生成。

**附带修复（实现中发现）**

1. `app.py create_task` 无截取参数时 `segment_temp` 未定义 → HTTP 500
   （上游 HEAD 即有的存量 bug），单独修复提交
2. modelscope 传 model id 必联网核对版本，本机系统代理失效时离线环境直接
   `model not registered` → 新增 `_local_model_dir` 缓存优先解析（命中本地
   完整缓存即传目录路径，绕开联网核对；未命中回退 id 正常下载）——cam++
   未缓存的机器首次仍走下载，已缓存机器完全离线可加载（对应设计 D2 离线关切）
